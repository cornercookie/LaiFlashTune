### 日誌

1. 改寫 `open_with.rs` 的 `Sanitizer`，保留 HTTP(S) 網址識別、尚未判定的 authority（主機與可選帳密部分）、查詢狀態與安全輸出。前綴未完成時保留最多正辨識中的前綴，非網址一般文字在繼續辨識或完整字串結束時寫回。網址已到路徑後的 `@` 保留。
2. 在判斷 authority 完整以前不寫入輸出。遇 `@` 遮蔽 userinfo，輸出僅保留安全的主機部分。正常分隔或 `sanitize_log` 的輸入結束時只寫出可辨認的主機／連接埠，格式有疑義時捨棄待定區段。一次性 `sanitize_log` 的輸入可正常結束。兩個 stderr 消費者都只寫出已由分隔字元確認的部分。子程序 EOF 也可能來自逾時或輸出超限，單靠 `Ok(0)` 或取消旗標無法確認輸入完整。任何 n > 0 的讀取都延續狀態。取消、輸入提前中斷與讀取錯誤捨棄待定 authority。保留 `***@` 遮蔽格式。
3. 待定 authority 及安全輸出分別以 1,024 bytes 為上限。authority 超標後進入丟棄狀態，跨區塊持續到空白結束，不將後半段當一般文字。清洗後已確認安全的輸出才加入結果，在字元邊界截斷，不跨越 1 KB，不延後到累積整段 stderr 後才限長。一般文字的問號沿用既有清洗規則，從問號隱藏至下一個空白，跨讀取區塊同樣有效。維持只輸出既有的 ASCII 可列印字元、空白、Tab、CR 與 LF。半個網址前綴在不完整收尾一併捨棄。既有的輪替和路徑遮蔽流程不變。`file://` 在現有清洗器未成功辨認，本期需求的 HTTP(S) 處理不新增檔案 URL 解析。
4. 完成條件沿用 #1。用無敏感測資，驗證同一合成 HTTP(S) 網址每個切點與不切分時在相同收尾模式下結果一致。測資結尾若停在可辨認 authority，完整字串保留主機與可選連接埠，兩個 stderr 入口的收尾捨棄。若已有分隔字元，兩種收尾保留相同的已確認內容。另核對 ASCII 普通文字、截斷、換行及中斷後不輸出待定內容。風險是過度遮蔽普通網址或誤留不完整欄位，測試需同時比對保留與清除的內容。

### ReplayGain

1. `src/types.ts` 與所有 `playerStatus()`／`EngineSnapshot` 消費點對齊 Rust 現有 camelCase，用實際序列化鍵覆蓋舊欄位，包括位置、播放狀態、曲目識別、待播世代與 ReplayGain。既有正確的鍵（如 #6 的 `volumeDb`）保持不變。AppConfig 及其他資料模型的 snake_case 保持不變。
2. `player.rs::publish` 從實際供本機 `PlaybackCore` 取樣使用的 `EqProcessor` 發布 `appliedReplaygainDb`、`appliedPreampDb`、`hasReplaygain`、`rgSource`，以及 `EqShared` 的 ReplayGain 使用者選擇 `rgMode` 和 `volumeNormMode`。以 `EqShared` 為模式與專輯上下文的唯一來源。電台、沒有有效本機軌或已停止時清空有效增益與來源，模式值仍反映目前設定。對應的前端欄位按 `serde_json` 實際鍵名測試。
3. 在 `eq.rs` 記錄 ReplayGain 正規化分支的有效增益，等於曲目或專輯增益加 RG 前級並套用峰值限制，轉回 dB。無標籤使用其前級。這個值不含 EQ 前級、音量滑桿或增益過渡中的瞬時值。處理器更新後才發布，暫停下的模式變更也透過設定更新路徑刷新。Peak／Off／RG Off 的增益值為空，`appliedPreampDb` 為 0，來源維持對應語義。
4. 將每曲的正規化 context 套用收斂至共同本機載入／換軌落點。直接 Load、Prepare、同軌重定位、手動換軌及自然換軌之來源，都用其自身標籤及峰值正規化資料更新處理器。保留 B 批要接通的預載串流入口。`TrackResampler` 的既有當前軌資訊涵蓋記憶體及長檔，補齊 `path`／`decoder` 並以短鎖擷取一次快照，供 publish、seek 與音效上下文共用。Seek 在拆除舊軌前擷取此快照。不以是否有曲庫 ID 判斷是否具備有效本機軌，因外部開檔可為 0。直接載入與自然換軌都以每曲資料設定 `set_rg_context` 與 `set_norm_gain`，避開只讀未寫入的核心模式副本。已存在的串流直接載入路徑一併接上，本批不實作 B 批的新預載交接。
5. `Shell.tsx` 及 `Tools.tsx` 依 `RG_Track`、`RG_Album`、`RG_Track_Fallback`、`RG_None` 與非空有效增益顯示。其他來源不顯示正在套用 ReplayGain。只有 `RG_None` 顯示使用無標籤前級。顯示模式值可為 auto，具體套用曲目或專輯由來源欄區分。
6. `Shell.tsx` 的手動載入與自動預載都使用同一遞增播放請求 token 序列，既有 `resumeToken` 只用於還原工作撤銷。送 Load 前記錄待確認的手動 token 與最近已處理的播放序號。引擎在真正安裝手動 Load 成功或終態失敗時，更新可空的 `lastManualLoadResult { token, outcome }`（`outcome` 為 `loaded` 或 `failed`），在同一次 publish 與新身分或錯誤一起發出。前端只用此終態匹配待確認的手動 token，不用 `nowToken` 或錯誤字串推測。前端 token 直接傳入共同 `load_at` 落點，寫入當前軌與重取樣器資料，避免 `sync_identity` 覆蓋。非手動載入不寫此終態。待確認時舊快照不觸發換軌、排隊、歷史。播放序號由引擎單一遞增計數器在實際安裝新曲且開始播放時配發，包括手動、同一首重播及自然換軌。預載不配發，Seek／重開保留原值。啟動還原的 Prepare 僅恢復身分並標記尚未開始播放。第一次有效 Play 或 Toggle 成功從已準備狀態開始，才清除此標記並給一次播放事件。已開始曲目的任何暫停恢復或裝置重開均保留播放序號。Seek 保留該曲目原有的首次播放標記，Stop／PlayUrl 清除。前端只處理嚴格大於已認領基準的序號。手動成功不依賴 songId 是否已顯示。在第一個 await 前同步認領序號並清除手動待確認 token，才執行一次應有副作用（正 ID 記歷史、更新歌詞、計算下一首）。等待返回時，已有較新的播放就捨棄過期結果。自然換軌也先認領再執行。失敗或 IPC 拒絕只釋放本代等待，標記已收到的序號為已處理，不重播舊歌副作用。等待期間持續記錄最大已觀察播放序號，供 IPC 拒絕送出且無後端終態時使用。再測同號訊號不會冒充、失敗後不跳回，以及手動成功只執行一次。清下一首時不可歸零共用請求 token。外部開檔、拖放與列表點歌共用手動 Load 入口。初始化新計數器前，以快照中 `nowToken`、`nextToken`、`lastManualLoadResult.token`、`manualLoadTokenHighWater` 的最大值為下限。引擎收到嚴格大於 `manualLoadTokenHighWater`的手動 token 才受理並先更新這個水位。水位預設為 0，受理後立即可發布，即使等待淡出或準備來源。小於或等於水位的重複或亂序意圖不得裝軌、撤銷較新意圖或改寫較新的結果。A 單獨交付時須包含上述配號規則，B 接通新交接路徑時沿用。
   載入成功之前保留最後確認身分，於新來源實際安裝後才寫入新 seq／token。直接 Load 與淡出後載入的成功／失敗共用終態處理。載入失敗時停止輸出、撤銷待播、清空本機曲目身分、位置與長度，狀態轉 Finished 並發布固定的載入失敗錯誤文字。原始錯誤只進既有 1 KiB 清洗日誌，下一次成功載入清除錯誤文字。失敗維持最後的播放事件序號，UI 以對應的 failed 回執解除本代等待，歷史及佇列不變。驗證在路徑不合規、通過路徑但解碼失敗、淡出後載入失敗時均有相同結果，逐項核對 sink 停止和欄位無新舊混用。真正的手動 Load 以命令 token 發回執。舊的 IPC Next／Prev 待辦使用候選播放身分，可能沒有前端等待的手動 Load token，因此不改寫手動回執；成功播放則仍給新序號。前端 Next／Prev 改走手動 Load 後沿用共同入口。受理較新的 Load、Stop、Prepare、PlayUrl 或舊的 IPC Next／Prev 時先撤銷互斥待辦及其淡出世代。舊 IPC Next／Prev 自身不建立手動回執，但若實際撤銷仍等待的手動 Load，必須對被撤銷的原 token 發 failed。若被撤銷的待辦持有仍等待的手動 token 且沒有更新手動意圖，在同一發布回 failed；不覆蓋更新 token，也不將停止／還原當作新的播放事件。測試覆蓋撤銷與真正安裝的 token。
7. 完成條件沿用 #5。核對至少這些獨立行為：序列化鍵、曲目與專輯選取、無標籤前級、峰值限制結果不混入 EQ 前級、關閉後狀態清空、換載新曲不沿用上一首值。保留 #6 及所有相關 JavaScript 測試。風險是調整正規化初始化時破壞峰值模式或切歌狀態，必須以個別音軌資料驗證。

### 實作步驟

1. **固定交接點。** `PlaybackCore` 在舊軌源、重取樣與 DSP 尾段都排空後進入一次自然交接。從 `TrackChain::next` 移除直接取待播槽的旁路。保存一次性 `gap_remaining`，以 `gap_ms × 48,000 × 2 / 1,000` 遞減。零停頓直接接下一軌。尚未準備完成可等同世代結果，停頓不得重啟。只在安裝新軌後發布新 seq/token 與原檔時間基準，舊軌停頓期間不增計進度。停止、重新定位或手動換軌撤銷這個自然交接。
2. **來源準備與生命週期。** 目前軌、待播軌及回收中工作共用 P0 Design 的三份配額。受理前取得，直到來源與作業完全釋放為止。用一筆帶世代、seq/token、格式（明確 Symphonia／FFmpeg）、原檔起點、總長、正規化資料及來源的結果取代分離的 pending 狀態。準備工作擷取世代，完成時不得從核心回讀新世代蓋掉舊值。舊軌播放中在背景完成來源、`TrackResampler` 與 `RateStage` 建立。串流至少有一個完整原生聲道幀才發 ready，空來源回報失敗。取樣端在交接點只做非阻塞接收與交換，不分配或建立重取樣器，不等命令 tick。用配額保證每筆來源預留回收槽，過期或舊來源非阻塞移交，音訊回呼不析構 FFmpeg。tick 發布資料與消費完成通知。兩端於世代改變時都核對身分。已暫停時保留暫停。丟棄工作連同完整來源移交有界回收。FFmpeg 只啟動一次，每個進程有自己的取消旗標，避免原物件 Drop 取消新來源。直接 Load／Seek 與預載共用背景工作及配額。新手動意圖先撤銷待播，只保留最新一個輕量請求，等回收釋出名額。取消、暫停、停止仍可在命令迴圈處理。停止後或暫停下不自動啟播。超過 P0 的回收期仍無名額時，回報本代無法載入，原始錯誤僅寫清洗記錄。
3. **PCM 及取消。** Symphonia 在 worker 逐樣本以 PCM 位元組計數。限制分配容量與邊界讀取，避免向量倍增及剪靜音再複製全段 PCM，剪除使用原地操作。FFmpeg 由有界通道傳回 stdout 區塊給監督者，以相同上限驗證，確認 EOF 恰好到限仍成功。超過 400 MiB 則丟棄部分 PCM，確認子程序及部分記憶體回收後以同世代／seq／token 從原起點轉串流。記憶體上限包含所有直接與預載的 Symphonia／FFmpeg PCM 收集入口。轉串流開啟也失敗時才回報失敗。ffprobe 保留 64 KB／10 秒／4 槽。短檔收集或開流首批資料連續 10 秒無新區塊才由監督者取消並安排回收。已建立的串流只在 Playing 且消費端持續空讀時計時，待播、暫停與緩衝已滿都不算停滯。來源從有界通道以 `try_recv` 回報資料、暫未就緒、結束或帶型別原因的失敗。配置拒絕與普通解碼／I/O／停滯失敗分開，拒絕狀態不得被後續成功或 EOF 覆蓋。未交接的候選在發出 ready 後若收到配置拒絕，同 token 改發 failed，捨棄該候選的緩衝並禁止安裝。安裝與來源終態以同一世代的原子狀態切換判定先後，若拒絕晚於安裝則走目前軌失敗流程。以可控背景來源測試 ready 後、切換前拒絕及切換後拒絕。暫未就緒輸出完整左右聲道靜音幀，繞過重取樣與 DSP，不前進歌曲時間或觸發交接。播放中終態失敗回報有界錯誤，依既有略過規則處理有效已備候選，沒有候選時結束當前播放。FFmpeg stdout 與 stderr 分開處理，所有本批入口 stderr 用 #1 清洗器，保留本機 file,pipe 協定白名單。回收按 P0 的 10 秒及後續 30 秒孤兒追蹤規則處理。容量不足拒絕新準備並回報，不讓音訊回呼持鎖等待。Symphonia 探測若不可中斷，工作留在同一配額下的獨立背景工作，禁止它卡住唯一可受理準備請求的監督迴圈。逾時回報後，其配額仍保留到工作實際結束。
4. **淡出指令流程。** 同一命令 tick 處理 `done_target`、有效來源與失敗。即使 recv timeout 沒有新命令，也要消費事件。Pause（包括睡眠到期）、Toggle、Stop、Seek、使用者點歌的 Load、Next／Prev 用相對包絡係數 0～1。Sink 已處理音量，包絡不能重套音量。沿用 #7 的各自淡出／淡入設定。暫停、沒有效來源、時間 0 時不等待不存在的輸出。將待辦的 Load／Seek 位置與是否繼續播放分開保存。淡出期間 Pause／Toggle／Play 更新意圖，保留同代 Load／Seek 目的。沒有待辦的暫停淡出中按 Play，從目前係數淡回並取消暫停。停頓或暫無來源的靜音下立即處理指令，暫停保留剩餘停頓。新 Load／Seek 取代舊目的，Stop／PlayUrl／Prepare 撤銷不相容的目的、待播與串流，手動載入以終態回執結案。暫停 Seek 保持暫停；開始與繼續分用 play/resume。前一首／下一首在前端依現有歌單規則解析後進入同一 Load，不把 Prev 指向待播下一首。失敗保留錯誤，不發布已播放的新身份。
5. **長檔去除開頭靜音。** 開啟去除靜音且初次正常播放時，背景準備統一以多聲道幀判斷，首個有效聲音停止掃描。採 #7 Design §9 的 60 秒音訊／50 MiB PCM 工程上限及獨立 10 秒期限，取先到。成功找到聲音後，重新定位到原檔對應的起點；到讀取量上限仍全靜音、期限到達或普通剪靜音探測失敗時回退原檔起點。探測回報配置拒絕時直接終止，不重開也不走 FFmpeg。原始開流也失敗則回報錯誤。Symphonia 和 FFmpeg 同樣適用，FFmpeg 起始偏移由實際開流入口傳入。原檔總長不變，進度及 seek 共用原檔時間，手動重定位與重開來源不重掃，不重加原偏移。關閉時不掃描。背景尚未完成時 Play 僅更新播放意圖，Seek、Stop、切歌撤銷過期結果。剪靜音有失敗回退及全靜音可播放假設，列為工程選擇。
6. **時間、待播回執及來源游標。** 所有短檔路徑在修剪前取得原檔總長，頭尾偏移存原生 frame，換算時只除取樣率。Seek 及重開用原檔座標且不疊加偏移。短檔 Seek 從原指定座標開始並使用原檔總長中繼資料，短檔 FFmpeg 也傳入起點。前端不另增原檔起點，尾端沿用首次修剪的原檔絕對終點 frame，不重新修剪。Seek 到達或越過有效終點時，屬於正常曲終而非來源準備失敗。暫停時保持暫停，恢復後執行曲終規則。驗證等於終點及超過終點。Symphonia 的共用預檢後歸零，依 C1 的同 handle 契約。預載向前端回報相同 token 的唯一進度狀態。前端每次依已確認新 `playSeq`、佇列、模式、清單、「播完停止」更新待播。引擎撤銷待播時遞增 `nextClearEpoch`，前端獨立觀察，暫停／播放中 Seek 均可重排。前端記錄已宣告的候選或「無下一首」以及播放序號、佇列、模式、清單和播完停止狀態的期望值。同一個無候選狀態不重送清除，避免 epoch 自我循環。同一播放序號的 Seek／重開保留明確無下一首標記，只撤銷候選來源。新播放序號重新宣告。自動預載一律按既有曲終規則。忙碌拒絕為可重試，前端保留一個最新候選，以送出該請求前已觀察到的 `nextCapacityEpoch` 為比較基準。忙碌拒絕抵達時，若目前值已大於基準就立即重送一次，否則只在後續前進時重送一次。同一容量狀態不反覆重送。準備或開流終態失敗時避開該候選直到歌單內容或當前曲目改變。既有清除指令以可選「沒有下一首」語意區分明確無待播與暫等，明確無待播且曲終轉 Finished。維持既有 Tauri 授權。
7. **修正 #4 的證據。** 兩個不同訊號都經正式交接入口，區分第二軌與舊軌 DSP 尾音，驗證交界相對原理論位置 ±5 ms 及第二軌至少 50 個樣本。使用非零 EQ，對照濾波器連續狀態與相同輸入的應有輸出。背景滿載測試使用有界、可同步的 fixture/測試接縫，明確保證完成槽先滿並送第二筆，證明 `set_next` 不等待 worker，最後必須收到最新請求的 token 與完成結果。驗證走實際取樣及命令通知流程，不能只用準備好的同步物件跳過交接。保留 Q3 正常 fixture 不啟動 FFmpeg。
8. **修正 #7 的證據。** 用空音源裝置可執行的核心測試驗證。記憶體下一軌與串流下一軌皆維持指定樣本停頓、0ms、晚到來源、撤銷世代。驗證淡出完成以前不做 seek／pause／stop，短檔剪靜音與長檔開關兩態保存位置。測試以合成 WAV 和可控的完成通知，不依機器有任意外部音檔。原設 #7 聽感項目仍需實機驗收。

## 4. 修復 C：標籤及封包的配置前限制

資料表與支援格式不變。分為 C1（可獨立修正的來源偏移）及 C2（解析器分配界線）。C1 的結果不得標為整個 #2 完成。

### C1 預檢與解碼共用來源

`audio_decode.rs:38–55、325–332` 預檢向前讀取 header、可能另移動游標，之後以共用游標的 File clone 啟動解析。`player.rs:538–542` 等多處在外部先預檢再進入 `SymStream::open` 造成重複。讓 `precheck_packet_budget` 從位移 0 判讀並還原進入時的游標；`SymStream::open` 在同一 File handle 上預檢後明確 seek 至 0 再交解析器。預檢成功或錯誤都嘗試回復進入游標，定位或還原失敗回傳錯誤。保留既有直接載入與預載的外部預檢，避免超限的拒絕落入通用 FFmpeg 後備。C1 不改 Windows 開檔驗證規則，B 另接到受驗證的原路徑。用 repo 既有正常 WAV 與合成 FLAC 的非零初始游標驗證游標還原及由檔頭正常解碼。用預檢結果的防禦性分支測試檢查拒絕不觸發後備。

技術實作以補丁式維護鎖定版本的已授權原始碼為候選。更新 `src-tauri/Cargo.toml` 的 crate override，記錄不受影響的預設 API、原授權及來源。先由獨立 Code 階段核對每條容器落點與安全更新策略，再進 C2。若核對後需改用新版，須用實際鎖定原始碼證明相同保護，不能靠新版聲明。內部 buffer 使用檢查過的長度與加法，巢狀區塊每層受於實體檔案與父區塊邊界，預檢及解析共用同一受驗證檔案來源。MP4 正常長度越過父區塊或位址運算溢位時拒絕，不允許失敗後切到未保護模式。

驗收使用一般小型音檔、帶一般封面的受控 fixture，以及對預算檢查器的邊界測試，證明跳過內容的路徑確實未讀取該 payload，合法欄位與原播放支持仍成立。預算拒絕、格式無法支援及正常 EOF 分屬不同結果。預算拒絕不轉 FFprobe／FFmpeg。播放中限制觸發保留終止原因，收集器不能把截斷 PCM 當成功。以原規劃為準，第 11 次跨封包解碼錯誤才終止。掃描的新預算解析器就緒後，移除「按外層含圖片總量拒絕」及「有封面整檔拒絕」閘門，由共用文字預算取代。風險是需要更新多個解析器、相容性後備不足、掃描用選項被誤套到標籤寫回。無證據的容器不得報為已關閉。

### C2a 解碼錯誤累計

`audio_decode.rs::SymStream::refill` 計數不因成功封包重置，`decode_errors > MAX_DECODE_ERRORS` 時才終止。既有上限常數仍為 10，呼叫端預期在累計第 11 次解碼錯誤停止。驗收確認這項差異並執行 Rust 測試。C2a 不變更封包配置、格式支援、後備或其他錯誤分類。

### C2b 預算拒絕在播放流程的傳遞

只覆蓋鎖定的 `symphonia-format-isomp4 0.5.5`，在 `demuxer.rs:536–541` 配置樣本 buffer 前檢查資料長度，普通及 fragmented 走同一入口。超過 256 KiB 回既有 `Error::LimitError`。此步只保護樣本配置，不涵蓋 moov 索引表配置或中繼資料。MP3 的 MPEG 標頭檢查與計算限制在 2,881 bytes，其配置落點 `symphonia-bundle-mp3/src/demuxer.rs:477` 直接用受限的 frame 長度。ADTS 長度欄位是 13 bit，最大 8,191 bytes，配置使用檢查後長度。MP3／ADTS 以鎖定原始碼核對，沒有新套件改動。Ogg、FLAC、RIFF 狀態不隨本批關閉。

**獨立度：** 可在隔離副本先準備及獨立審查開檔 guard 與型別化終態。與 B 的橋接驗收通過後再整合交付。交付範圍包含播放中拒絕，依賴 B 的背景來源終態通知和收集器。B 完成並驗證串流拒絕前，C2b 不得視為關閉。不要在仍只有 `Iterator<Item=f32>` 的路徑上把拒絕當成 EOF。

補丁存放 `src-tauri/vendor/symphonia-format-isomp4`，保留原授權。新增 `UPSTREAM.md` 記錄來源、版本、原 registry SHA-256 `243739585d11f81daf8dac8d9f3d18cc7898f6c09a259675fc364b382c30e0a5`、修改位置與更新方式。Cargo path override 後，核對 `cargo tree` 的路徑以及套件內測試，使用 `cargo test --manifest-path src-tauri/vendor/symphonia-format-isomp4/Cargo.toml` 及 App 測試，確認實際建置用到此補丁。使用正常 MP4、MP3、ADTS 樣本及單獨的預算計算／型別化結果測試，避免以異常內容重現。

### C2d 掃描文字預算與後備

每檔共用一個預算，包含重複欄位及 ReplayGain／R128，使用檔案順序且無優先欄位。每欄的值在配置前依宣告輸入位元組長度檢查；解碼後以實際 UTF-8 長度再檢查 4 KiB。總量依已接受的 UTF-8 鍵和值計 16 KiB；vendor、不可用的二進位或圖片在配置前略過，不轉為字串。鍵名須在既定 4 KiB 內辨認或略過，不能無界收集。已接受的重複項會計入總量，最後投影沿用既有欄位優先規則。超出單欄略過，總量用完保留已接受文字，後續欄位只走有界跳過。ID3 unsynchronisation 與壓縮採流式讀取／限額解壓，禁止一次配置整段標籤。Ogg 圖片欄位先用有限的欄位名稱辨識，再跳過至該欄結束，不累積 base64 正文。每格式由同一原始 File handle 判讀與解析，受限路徑啟用後才移除該格式舊預檢。選項僅供掃描，寫回仍使用預設解析失敗及保留封面語義。

| 結果 | 既定處置 |
| --- | --- |
| 文字單欄或總量超限 | 略過該欄或後續欄，保留已合法接受的文字。超量部分不配置，不改走後備。 |
| 容器標頭或欄位長度無法安全定位 | 回報損壞，停止讀取該檔，不嘗試用工具跨過已判定的安全限制。 |
| 工具矩陣聲明的格式不由 Lofty 負責 | 既定 FFprobe 路由，子程序輸出／時間／配額與播放器端解析各有上限。FFprobe 本身的配置不列為 Lofty 限額驗證。 |
| 副檔名與 magic 不一致 | 仍由實際辨認到的容器套用其 guard。只有既有支援矩陣中的實際容器可走匹配路由，沒有可驗證的受限解析路徑保留未決。 |
| 本機檔案 I/O 錯誤 | 掃描拒絕或跳過並回報，不讀取同一路徑的第二份內容假作成功。 |
| 正常完成 | 回傳合法文字及原有音訊中繼資料，持久化原有欄位。 |

C2c／C2d 仍須逐容器核實讀取來源、保護選項與相容性。已知公開套件原文摘錄在 `SL-fixes-evidence/C2-locked-source/crate-excerpts.txt`。任何格式保護無法證明前，該列維持待修。

#### C2d-FLAC 原生 FLAC 的掃描子範圍

鎖定 `lofty 0.9.0` 的 `src/probe.rs::ParseOptions` 支援 parsing mode，沒有圖片或欄位上限。現行 `flac/read.rs::read_from` 先由 `Block::read` 收入整個中繼區塊，才辨認文字與圖片；`ogg/read.rs::read_comments` 先配置輸入再辨認項目。掃描以局部套件補丁增加受限入口，沿用原生 FLAC 音訊屬性計算與 TaggedFile 欄位映射。[FLAC 格式 RFC 9639](https://www.rfc-editor.org/rfc/rfc9639.html#name-metadata)

1. `scanner.rs::process_single_file` 在兩個舊標籤／封面預檢之前，以單一函式使用 `open_validated_file` 啟用原生分流。檔長、第一個 4-byte 標記、rewind 及後續解析使用同一 handle。檔長不超過既有 `LOFTY_MAX_FILE_SIZE`（50 MiB）且第一個標記為 `fLaC` 才選受限路徑。已核對標記為其他實際內容時沿用舊路徑；超過 50 MiB 的原生 FLAC 明確維持原本的既有大檔工具分流，尚未進入此受限入口。禁止後備的規則適用於選定受限入口之後的任何失敗。開檔、檔長、標記短讀或 rewind 的 I/O 失敗回報 Skipped。已選定受限路徑的格式錯誤回報 Rejected。兩種失敗均用固定原因及遮蔽路徑，新檔不入庫，現有且仍在磁碟上的曲目保留原資料，待下次成功掃描更新。
2. 在 `src-tauri/vendor/lofty` 建立 v0.9.0 局部補丁，保留授權及來源 checksum。App 以 `[patch.crates-io]` 與鎖檔使用補丁。新增 `pub fn read_native_flac_for_scan<R: Read + Seek>(data: &mut R) -> lofty::Result<TaggedFile>`，保留現有 `FlacFile` 轉 `TaggedFile` 的欄位映射與 `flac/properties.rs`。應用函式將成功結果直接交現行 `lofty_result` 欄位選取。已選定的檔案跳過舊兩個預檢與掃描時的一般 Lofty／FFprobe 路徑。此限制包含後續封面與時長補查，成功但缺少文字走既有檔名回退，缺少音訊資訊沿用既有資料未知／拒絕語義。掃描目前的 `cover_path` 是 `None`，成功路徑仍不產生內嵌封面縮圖。寫回與其他讀者仍用原有入口。
3. 受限入口從相同 handle 開頭驗證 `fLaC` 及第一筆 type 0、34 bytes 的 STREAMINFO，使用固定陣列。區塊標頭以讀取位置、u24 長度、checked 加法及實際同 handle 檔長核對。除 type 1 與 3 外，零長度區塊拒絕。PICTURE、Padding、Seek Table 及不解析的區塊只 seek 至已核對的結束位置。固定 34 bytes 僅接受標準 STREAMINFO，歷史上可能被接受的非標準長度會拒絕。掃描跳過圖片內容，不驗證圖片編碼，也不為僅有圖片的檔案建立空 Vorbis tag。保留被略過區塊的界線檢查，沒有宣稱保留圖片格式驗證。
4. 於每個 Vorbis comments 區塊依剩餘位元組逐次扣除每個 4-byte 長度或項目數量欄位本身，再核對 vendor 與各 item 載荷不超出區塊剩餘位元組。vendor 和分隔符不計文字額度，vendor 不配置及不做 UTF-8 驗證。不依宣告數量或未核對的長度 reserve。用可重用 4 KiB 緩衝只讀至第一個 `=`。累計到第 4,096 個鍵位元組後，僅在 item 內尚有位元組時，再以一個額外的單 byte 讀取辨認第 4,097 個位元組是否為分隔符。允許 1～4,096 個 ASCII 鍵位元組，沿用 Lofty 的 0x20～0x7D 且排除等號規則。超長、空鍵、失效鍵或沒有等號的欄位，定位至已核對的 item 末端。值的位元組最多 4,096（等於可接受）。`METADATA_BLOCK_PICTURE` 與 `COVERART` 一律採 ASCII 不分大小寫比對跳過。兩者皆先辨認鍵，值不得讀入。`used + key_len + value_len <= 16384` 才配置並驗證所接受的值為 UTF-8。已接受的值若不是合法 UTF-8，沿用原解析失敗語義並回報 Rejected。放不下的欄位略過，後續較短欄位可收。被略過的值不驗證 UTF-8。累計跨同檔區塊，含已接受的重複項，以檔案順序消耗，排在後面的 ReplayGain 或 R128 可能因額度不足略過。
5. 各欄位長度不可跨出目前區塊。讀取完宣告的項目後可 seek 略過區塊內剩餘位元組。從最後一筆中繼區塊的結束位置計算音訊資料長度，音訊取樣率、聲道、時長及位元率沿用既有屬性函式，下游 8,000～384,000 Hz、1～8 聲道驗證維持。受限入口的底層 File 不使用讀取預補。驗收以底層追蹤 reader 核對正常 FLAC 的圖片內容僅經 seek 跨過。普通封面與合法文字樣本走同一 `process_single_file` 入口，驗證標籤、ReplayGain、時長、掃描路徑及預設寫回的相容性。以數值及模擬錯誤驗證 4 KiB／16 KiB 邊界、重複項合計、拒絕不回退與入庫結果。帶 ID3 前綴、既有大檔工具路徑、Ogg 封裝與播放端 FLAC 防護仍屬各自待修範圍。
### C2e 播放探測欄位與 ffprobe 上限

既有 `audio_decode.rs::ffprobe_json` 的 stdout 工作以無界通道送資料，只有收集完成的陣列受 64 KiB 限制。逾時及超量分支提前離開，可能在子程序及工作仍存在時釋出配額。此子範圍修復應用端管線，與播放器 C2b 的包配置拒絕有各自的入口。

1. 共用探測入口保留絕對本機輸入路徑及 `file,pipe` 協定白名單。以固定選項區分播放與掃描。播放用 `-show_entries stream=codec_type,codec_name,sample_rate,channels:format=duration`，保留 JSON 格式選項，播放選項不再帶 `-show_streams` 或 `-show_format`。仍按既有順序選第一個音軌，缺漏值仍依各呼叫端現有規則處置。接通 `FfmpegStream::new`、直接載入、兩條預載路徑及未接生產的 `next_track.rs`。掃描維持原 metadata 輸出，標籤預算由 C2d 處理。此投影只限制工具寫給應用端的內容。[ffprobe 官方文件](https://ffmpeg.org/ffprobe.html#Main-options)
2. 以兩個最多 8 KiB 的資料訊息限制 stdout 通道，讀取端另持一個固定區塊。累計接收資料先查剩餘額度，陣列容量不超過 64 KiB。剛好 64 KiB 到 EOF 可解析，超過即拒絕整筆。stdout 讀錯與管線中斷都不是 EOF。僅在完整 EOF、子程序成功結束、無讀取錯誤且在期限內時解析，任何失敗不回傳部分 JSON。stderr 使用 A1 清洗。
3. 全域最多四槽，10 秒限制呼叫端的等待時間，包含取得槽位、讀取及退出通知。等待槽位耗盡期限不得啟動子程序。取得槽位後以可失敗的方式先建立背景探測工作，由該工作啟動及全程擁有 Child、配額與兩個讀取工作，因此中途不需建立回收者或移交所有權。子程序啟動後，所有未完成的路徑（包含逾時、超量、無輸出管線、讀取錯誤、管線中斷、查詢退出狀態或建立讀取工作失敗）都立即丟掉 stdout 接收端、終止並等待 Child，再 join 已建立的工作。只有證實 Child 已回收且工作已 join 後歸還配額。終止或等待失敗時保留資源與槽位並重試確認，呼叫端在原期限內得到固定錯誤。若四槽皆待回收，後續探測依既有等槽規則逾時。啟動前的工作建立失敗可直接歸還未使用的槽位。子程序錯誤不回顯原始工具內容，成功收到完整資料、退出成功與回收完成後才通知呼叫端。掃描與播放仍共用同一配額。
4. 以現有 WAV 和可從該檔離線轉出的正常 WMA 作為必要欄位對照，在掃描確認仍取得一般標籤。核對兩種模式的固定工具引數，以及目前所有播放探測實際讀的是四個音軌欄位與容器 duration。用有界的普通位元組 fixture 或模擬來源驗證剛好 64 KiB、超量一個位元組、讀取失敗、沒有完整 EOF、正常 JSON 但非成功退出、等槽逾時沒有啟動子程序，以及超量、讀取失敗或逾時後須保留配額，證實回收完成後恰好歸還一次。此子範圍涵蓋應用程式端累計與工具輸出，FFmpeg 內部解析／分配、C2d 掃描配置限制與 C2b 串流終態仍用各自的驗收條件。
## 5. 驗證及審查證據

先由 Claude CLI 依序取得 Design Spec、Code、Security 的可追溯結論，再交 OpenCode CLI 實作已核准項目。每批修正後收集差異、測試輸出與雜湊，交獨立 CLI 以同三階段審查。任何修改後的差異都重新交獨立審查。會改變行為契約的修正先更新 Design 再複審。Review.md 保存審查者、時點、對象、結果及限制，保留原歷史報告。

獨立審查只取得隔離副本的相關公開基線、修復設計與差異。審查資料不含本機對話、帳密、曲庫 DB、未追蹤的原始工作檔或 #8。Security 核對檔案、子程序、狀態與輸入的防護，採靜態檢查與防禦性單元驗證。

交付前跑 Rust release 與 Node 測試，重建 Tauri exe 並核對前端資源。播放驗收另保留測試能證明的波形／資料結果以及需要真人聽感的項目。依 AGENTS.md 將變更後的長期行為同步至受影響的 Agents 知識文件與 ROADMAP，執行既有提交前禁用詞檢查。每批實作與實際結果待後續填寫。

## 電台取流與子程序（v0.20）

保留使用者主動選取的 HTTP(S) 電台，包括區網 NAS、自架主機與自訂埠。只接受具有主機名稱的絕對網址，拒絕控制字元。播放快照固定顯示「網路電台」，日誌與 UI 回報固定錯誤。直接開啟音訊串流，沿用禁止巢狀清單的規格。

Windows 系統目錄的 curl.exe 負責唯一一次取流。固定參數依序包含 -q（第一個參數，停用個人設定）、--globoff、--silent、--fail、--location、--max-redirs 5、--connect-timeout 10、--proto =http,https、--proto-redir =http,https。使用 --url 及獨立 argv 傳遞網址，不啟用跨主機轉送認證。系統缺少 curl 時回報固定錯誤。命令列可能對具本機權限的程序可見。兩個子程序的 stderr 均接空裝置。curl stdin 接空裝置，stdout 的管線直接轉交 FFmpeg stdin。FFmpeg 以 -nostdin、-protocol_whitelist pipe、-i pipe:0 讀取。用 format_whitelist 限制為經驗證的直接音訊容器，排除播放清單及巢狀來源；FFmpeg 輸出為雙聲道 44100 Hz s16le PCM。開流過程不另做預檢 HTTP 請求。

單一管理工作持有兩個 Child，接收最新意圖與世代，等待舊代回收後才啟動下一代。換台、Stop、轉本機曲目及引擎結束均可喚醒管理工作。只保留最新尚未執行的意圖；音訊回呼不阻塞。啟動第二個程序或 stdout 讀取工作失敗時，回收先前成功啟動的全部程序。管理工作持續輪詢兩個程序、取消及讀取結果；取消、管線或子程序失敗均終止其餘程序。即使 kill 失敗也要確認兩個程序均已退出。讀取工作使用可取消的有界 PCM 傳送，保留跨 read 邊界的半個樣本。完成回收後 join 讀取工作，最後發布一次本代結果。引擎退出 join 管理工作。只有本代接收端可更新狀態。自然完成須兩者退出成功、正常讀取且確有音訊；取消安靜結束，異常退出發布固定錯誤。PCM sender 結束只代表資料耗盡。

驗收以正常合成 WAV 和本機 HTTP 伺服器追蹤實際請求。直接取得及轉址五次應解出已知長度 PCM；需要第六次時目的地不得收到請求且無音訊輸出。分別檢查內網受理、含帳密或查詢的網址遮蔽、正常 EOF、任一程序非零退出、讀取阻塞、通道填滿、半途啟動失敗、切回本機、快速換台及引擎退出。檢查實際 PID 的退出及當代終態。2026-11-27 於本機使用 Windows curl 與 FFmpeg 獨立驗證：零次及五次各解出 17,640 bytes，六次 curl 退出碼 47、零 PCM，HTTP 伺服器未收到最終目的地請求；播放器整合另驗。
