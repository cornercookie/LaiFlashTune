## 開發流程

每個任務照這個順序走，前一步沒完成就不進下一步。

1. **寫 Design.md**：放在 `planning/<任務>/Design.md`，一個任務一份。設計與實作步驟寫在同一份，不另外開 Implementation.md。內容：
   - 目標與範圍
   - 圖：依任務挑流程圖、時序圖或架構圖（Mermaid），用得上的才畫
   - 現況（附檔案與行號）
   - 做法與實作步驟（要改哪些檔、依什麼順序）
   - 資料變更
   - 完成條件（可量測、可重現）
   - 風險
2. **Design 審查**：依序做 Spec → Code → Security 三階段，每階段的阻擋問題修完才進下一階段。
3. **實作**：由 OpenCode（`opencode run`）照 Design.md 的步驟做；做法有變更就先改 Design.md，再改程式。主導的 agent 負責拆工作、核對結果、跑測試與建置。
4. **實作審查**：同樣依序做 Spec → Code → Security。
5. **收尾**：更新受影響的 `Agents/` 文件與 `planning/ROADMAP.md` 的狀態，重建 release exe。

## 專案指示檔與知識文件

- **指示檔：** 專案指示檔統一使用根目錄的 `AGENTS.md`。專案若仍有 `CLAUDE.md`，將其內容依下列分工併入 `AGENTS.md` 與 `Agents/` 後移除；專案沒有 `CLAUDE.md` 時略過。
- **`AGENTS.md` 只放跨任務都適用的通用規則**（工作方式、必讀順序、禁止事項、驗證方式），專案知識只用連結指向 `Agents/`，連結文字寫明「什麼情況要讀」。
- **`Agents/` 維護五個知識主題**，每主題一份文件：服務架構（含各功能的前後端歸屬）、系統架構、資料庫結構、業務邏輯、使用者權限。可依專案需要增加主題，但同一主題不拆成多份。
- **停用 `maintenance.md`：** 專案若有 `maintenance.md`，把 Agent 需要的資料與規範拆入對應的 `Agents/` 主題或 `AGENTS.md` 後停用；沒有則只建立並維護 `Agents/`。
- **開工讀取：** 只讀本次任務受影響的 `Agents/` 主題；任務改變架構、資料表、業務規則或權限時，於交付前回寫對應主題並更新其文件基本資訊。
- 知識文件以現有程式碼為準；與程式不一致時依程式修正文件，並於任務 Design 記錄差異。

## 文件分工

| 文件 | 撰寫與維護者 | 用途 |
| --- | --- | --- |
| Planning（沿用使用者的實際檔名，如 `planning.md`） | 使用者 | 需求、目標、範圍與限制。Agent 讀取並引用，未經明確指示不改寫、改名或刪除 |
| `Design.md` | Agent | 依 Planning 產出設計；實作時在同一份文件補上實作、審查、驗證與剩餘工作 |

- 任務文件以 Markdown 寫入專案的 `docs/<任務資料夾>/`，沿用專案既有目錄慣例；同一任務不拆成多個平行目錄。只有使用者明確要求才產出 Word／PDF。
- `Design.md` 是每個任務在開發流程中各自產出的文件，合併原本的設計與實作紀錄，不另外產出 `implementation.md`；整個專案不共用一份 Design.md，跨任務知識放 `Agents/`。
- Design 盡可能以 Mermaid 圖表呈現設計：流程圖、時序圖或架構圖，依任務挑選最能說明變更的圖，不必每種都畫；文字補充圖表無法表達的規則與契約。
- Design 保留 Planning 的來源連結與必要需求摘要，摘要不取代原始規劃。發現需求缺口或設計偏離時明列差異，不改寫 Planning 來配合實作。需求由使用者在對話提供時，引用該次指示，不自建 Planning 冒充使用者文件。
- 使用者要求 Agent 撰寫 Planning 時，依 `planning-writer` 技能以使用者的描述起草，經使用者確認後即為使用者文件；之後 Agent 未經使用者指示不得修改。
- Design 屬內部任務工作紀錄，審查紀錄與修訂經過保留在其中。`system-documentation-standard` 第 26 條「正式文件不得混入內部審查紀錄」適用於另行產出、交付客戶的正式文件，不適用於 Design。
- 設計階段寫預期行為與驗證方法，實作階段才填實際結果；保留重要設計修訂理由及前後差異，不事後改寫成從未變動。
- 跨任務持續有效的知識回寫 `Agents/` 對應主題（見「專案指示檔與知識文件」）。
- 格式使用本技能的 [Design 範本](assets/Design.md)；專案自有範本時依專案範本。系統文件另依 `system-documentation-standard` 及相應技能。

## 審查：兩個時點，每次三階段

審查在兩個時點進行：**設計完成後（實作前）** 與 **實作及驗證完成後**。每個時點都依 **Spec → Code → Security** 執行三個階段，分別保留結論，不能以一次籠統的「審查通過」取代。每個時點可複查多次直到收斂，次數不設上限。

| 階段 | 設計審查 | 實作審查 |
| --- | --- | --- |
| Spec（規格） | 將 Planning／需求原文與 Design 並排核對：範圍、前後端責任、適用的正常／邊界／失敗行為、契約與可判定驗收；不以 Agent 摘要取代原規劃 | 逐項比對 Planning、Design 與實際行為；檢查漏做、偏離、回歸與測試證據，確認未完成項目已明列 |
| Code（程式與可實作性） | 讀取受影響現有程式與呼叫者，審查預定修改路徑、相容性、資料遷移、並行與可測性；新模組尚無程式時審查設計契約並記錄限制 | 讀取實際差異及上下游路徑，檢查正確性、錯誤處理、持久化、相容性、測試有效性與可維護性 |
| Security（資安） | 檢查信任邊界、身分驗證、後端授權、資料裁切、敏感資訊、輸入、外部副作用及部署限制 | 核對實際程式與設定的授權／拒絕路徑、敏感資料處理、輸入與外部整合；依變更風險使用適合的資安檢查 |

純文件任務的 Code 階段審查來源、路徑、連結與規則可執行性；Security 階段審查資訊揭露與安全規範是否遺漏。仍須留下紀錄，不能聲稱已做產品程式審查或完整資安掃描。

### 各階段使用的技能

| 階段 | 設計審查 | 實作審查 |
| --- | --- | --- |
| Spec | 無專用技能，依上表並排核對 Planning 與 Design；系統規格文件另依 `system-spec-writer` 的品質檢查 | `code-reviewer` 的 `references/spec-compliance-review.md`：缺漏需求、多餘新增、理解落差 |
| Code | 無專用技能，依上表讀取受影響程式與呼叫者 | `code-reviewer` |
| Security | 無專用技能，依上表檢查信任邊界與授權 | `security-reviewer` |

使用這些技能時，本技能的規則優先：

- **範圍基準：** 以 Planning 與已確認決策為準。`spec-compliance-review.md` 的「缺漏需求」只計 Planning 要求的項目；其檢查清單中的邊界情境，Planning 未要求者不構成阻塞。「多餘新增」照常檢查，即擴充範圍。
- **分類對應：** 技能輸出的 Critical／Major／Minor 或 Critical／High／Medium／Low 嚴重度，不直接等於本流程的結論。符合「阻塞」定義且附依據者列阻塞；其餘列建議或範圍外。技能的 Verdict（Approve／Request Changes）改以本流程的「需修正／受阻／通過」記錄。
- **資安審查方式：** `security-reviewer` 只做程式與設定的唯讀審查，以及本機已安裝工具的靜態掃描。主動測試、滲透測試、對任何執行中環境的攻擊性測試，須使用者明確授權並界定範圍；正式環境不得測試。
- **來源：** `code-reviewer`、`security-reviewer` 取自 `Jeffallan/claude-skills`（MIT），commit `36f3fe8`，2026-10-21 安裝；Codex 與 Claude 各存一份。

## 發現、修正與複查

- **紀錄：** 每一階段記錄時點（設計／實作）、第幾次複查、日期、審查者及方法、審查版本與檔案範圍、發現位置與影響、修正、複查證據及結論，存於該任務的 Design。
- **結論：** 使用「待審查」「需修正」「受阻」「通過」。沒有實際審查或缺少必要證據時保持待審查／受阻。沒有相關風險時寫「已檢查，無此類變更」，不可跳過整個階段。
- **阻塞：** 只限核心行為不明確、權限錯誤、資料遺失風險、驗收無法判定，或可核對的事實錯誤。修正後複查該階段及受影響的後續階段。
- **阻塞須附依據：** 每條阻塞須指出所違反的 Planning／需求原文、已確認決策，或錯誤事實的檔案與行號；指不出依據者最多列為建議。「缺少某類邊界情境」本身不構成阻塞，除非 Planning 要求，或缺少它會使驗收無法判定。
- **建議與範圍外：** 建議不計入結論。會擴充範圍的建議最多列一行「供使用者決定」，未經同意不納入 Design。
- **最小修正：** 作者只修正阻塞，以更正或刪除為主，不以新增規格、邊界案例、驗收或測試作為修正手段；需要新增規格才能修正時，轉交使用者決定。
- **複查範圍：** 第二次起，審查者只確認上一次的阻塞是否關閉，以及本次修改是否引入新阻塞；未修改的內容不重新全面審查。需求或設計方向改變時，才對受影響章節重新全面審查。
- **交給使用者決定：** 同一階段連續兩次複查仍有阻塞，或阻塞數量未下降時，Agent 停止自行修改，把剩餘發現、各自依據與可行選項交給使用者。這不代表審查結束，使用者決定後照常繼續複查直到通過。
- **審查提示：** 委派其他 Agent 審查時使用 [審查提示範本](assets/Review-Prompt.md)；作者自審也依同一標準分類發現。
- **獨立性：** 審查回覆與作者自驗分開。有獨立審查者時讓其直接閱讀需求、Design、相關程式及驗證證據。未實際委派時不得宣稱第三方審查；不得擅自向外部模型傳送內部資料。
- **進入實作：** 設計審查三階段皆通過才能實作。涉及人員核准或外部操作時，另遵使用者授權；審查通過本身不授權發布或部署。
- **多 Agent 協作：** 開始時安排獨立驗證角色，持續檢查關鍵路徑與整合衝突；是否委派依使用者及當次指示。
- **知識回寫後：** 回寫若改變設計、權限或安全規範，複查受影響階段；最後檢查 Design、專案知識與實作一致。

## 交付判定

Design 必須包含實際變更、已執行的驗證及證據、設計審查與實作審查各三階段的紀錄、未完成項目與環境限制。功能完成、正式部署與真人驗收分別記錄；未部署不得寫成已上線。驗證方式依專案的驗證規則。

# 系統文件撰寫與審核規範

本技能管理系統文件的共同撰寫、審查與交付要求，不取代需求分析、架構設計或繪圖技能。首次套用時必須完整讀取 [28 條核心規範](references/core-rules.md)。該檔是使用者規範的唯一維護來源；以下為執行方式，依使用者澄清維持相同語義。使用者當次明確指示優先；相關技能及範本的預設與本規範衝突時，依本規範調整。

## 適用與協作

- 系統規格工作搭配 `system-spec-writer`；架構文件搭配 `system-architecture-doc`；圖表搭配 `system-architecture-diagrams`。僅讀取本次需要的技能，不為小幅文字修訂擴大工作。
- 本技能可單獨審核系統文件。使用者只要求審核時，列出問題，不擅自重寫。
- 共用規範與上述技能並列安裝；引用缺失時先確認路徑，無法讀取就說明缺失，不宣稱已套用。不得循環載入已讀取的技能。

## 撰寫與更新

1. 先讀已提供的需求與相關文件，辨識本期範圍、既定名稱、文件版本及可信來源。來源依可靠性、確認狀態與適用範圍判斷；已確認的內部需求、既有設計與程式碼可以使用，未確認草稿不作定案依據。正文先概述必要內容，再補充章節或來源連結，不要求讀者自行找其他文件來理解核心設計。
2. 文件預設使用台灣繁體中文，只有使用者明確要求時才改用其他語言；適用於正文、標題、圖表標籤及說明。使用客觀、精煉的主動語態。專業術語與代號首次交代中文名稱和意義，有通用或已確認縮寫時採「中文（英文縮寫）」。沒有縮寫時使用中文或必要英文全名，不為命名而創造縮寫或提出不必要問題。正文與圖表優先使用業務名稱；需保留技術名稱時先定義，不能讓閱讀者猜測。
3. 欄位定義與介面契約是第 24 條所要求的技術內容：可在欄位表、契約、程式碼區塊及確有技術必要的說明保留精確名稱，附中文業務意義與用途。未定義的自創變數或代號不得直接出現；一般業務正文使用業務名稱。
4. 先將各文件以 Markdown 寫入 `docs`，可依專案慣例使用子目錄。更新時沿用文件身分、版本與需求編號；既有檔案不在 `docs` 時不擅自搬移或刪除，指出路徑差異，依開發者明確指示處理。只在開發者要求後才轉出 Word 或 PDF。
5. 文件開頭提供「文件基本資訊」：名稱、版本、建立日期、更新日期與各章節變更摘要。日期與歷史版本沒有依據時不捏造。標題最多四級，細分使用項目符號或粗體。
6. 主動規劃資料流：來源、驗證與轉換、儲存、傳出及結果；同時交代正常、邊界及錯誤行為。將非本期實作項目集中於「非本期範圍（Out of Scope）」獨立章節。
7. 說明採用技術的選用理由。涉及架構與資料流時，獨立說明身分驗證、適用權限控管模型及傳輸加密標準；只有採用角色權限控管（RBAC）時才展開角色權限，不強制套用此模型。資訊足夠時建立非功能性需求章節，涵蓋效能、併發、資料保留及可用性；未知值列問題，不捏造。
8. 系統介接或 API 依實際協定描述契約。HTTP 介面包含方法、端點、欄位、請求、回應、狀態碼與錯誤代碼；其他介接描述通道或位置、資料格式、處理結果、錯誤及適用的重送行為，不硬套 HTTP 欄位。範例不得引入未確認行為。
9. 圖表優先保留 Mermaid 或其他可編輯程式碼，讀取相應圖型規範；名稱、資料庫、箭頭動作及正文一致。轉出 Word／PDF 時，圖號與圖名在圖下，表號與表名在表上。
10. 每個主要功能定義業務驗收條件與預期結果，依交付需求納入正式文件。內部交付前的品質檢查、自查流程與審核紀錄另存 `docs/internal/<主題>/Delivery_Checklist.md`；詳細測試案例可另存 `AC_List.md`，不因其為內部案例而刪除正式文件的業務驗收章節。Markdown 工作草稿可保留明確標示的討論、假設與待決方案；正式文件移除這些內容，必要待確認問題仍可列出，但不能寫成已決方案。

## 審核與連動更新

需要保存內部交付前檢查時使用 [交付檢查範本](assets/delivery-checklist-template.md)，不以該檢查清單取代正式文件的業務驗收章節。

- 審查架構完整性、設計合理性、與其他文件是否矛盾，以及來源可靠性。追蹤代表性資料從輸入到結果，檢查失敗後的資料狀態與恢復方式；核對技術選型是否支持需求。
- 長文件分章產出。每新增或修改一章，核對前置章節的名詞、元件、資料流、介面與圖表；同步更新受影響的資料描述及內部驗收，不只修正文句。
- 輸出審核問題時交代文件位置、證據、影響、修正建議與需開發者決定的事項；來源不足或架構矛盾要提出討論。可繼續不受影響的草稿工作，不宣稱疑義已解除。
- 使用其他 Agent 工具審核時，要求第三方專家角度，不暗示預期結論。提供文件、相關架構及必要來源，要求檢查完整性、合理性、跨文件矛盾、來源可靠性及缺漏情境；僅比對正確性、拼字或措辭不足以判定正式交付。此規則規範已啟用的審核，不強制每次編輯都委派 Agent，也不授權向外部服務傳送文件。
- 正式交付前確認：基本資訊與章節變更齊全、術語一致、無含糊措辭或表情符號、非本期內容獨立、資料流含例外、安全機制及技術理由明確、契約完整、內部交付檢查與討論紀錄未混入正文，業務驗收條件完整、來源可核對。關鍵疑義未解時交付草稿及問題，不能標示正式完成。
- 交付說明列出文件位置、已檢查範圍與待開發者確認事項。自查、第三方 Agent 意見、人員核准與測試結果分開，不互相冒充。
# 系統文件核心規範

以下保留原 27 條規範的編號，並新增第 28 條語言規範，依使用者於 2026-10-09 的澄清修訂第 1、7、10、11、22、24、26 條。目的是防止未定義代號、以跳轉取代說明，以及內部工作流程混入正式文件；不得把助理建議冒充使用者要求。

1. 首次出現的專業術語或系統代號，必須先定義中文名稱與意義；有通用或已確認的英文縮寫時採「中文（英文縮寫）」格式，後續可使用縮寫。沒有縮寫時使用中文或必要的英文全名，不自行創造縮寫。不使用閱讀者無從理解的自創變數或代號；確實需要新識別名稱時，先說明用途、業務意義與定義。正文以業務描述優先，例如「目標起始時間」；需精確交代介面欄位或技術契約時可保留名稱，但必須附中文意義，不讓代號取代解釋。
2. 規劃文件撰寫時也要一併討論 Data Flow。
3. 文件架構先各自以 Markdown 格式寫到 `docs` 裡，開發者要求再產出 docx 檔案或 PDF 檔案。
4. 架構規劃需要審核的內容涵蓋架構完整性、是否與其他文件架構矛盾、來源是否可靠；有疑義就提出來跟開發者討論。
5. 使用其他 Agent 工具審核時，應讓其以第三方的角度給予意見，評估架構設計是否完整、是否合理；僅比對正確性或用字遣詞，不足以達到可以產出正式文件的程度。
6. 避免在規劃文件中出現含糊不清的用詞，如「團隊算法訓練」，一定會被挑戰「這是什麼意思？具體來說要做什麼？」。
7. Markdown 工作草稿可保留清楚標示的內部討論、假設與待決方案。正式文件保持客觀專業，移除口語化討論過程及未定案的推測性描述；決策背景轉化為客觀的技術選型理由或業務需求背景。正式文件可列具體待確認問題，不把未決方案寫成已核准設計。
8. 明確界定系統範圍（Scope）：正式文件應專注於本期將實作的功能。若有在需求訪談中提及、但「本期不實作」的項目，嚴禁與正式功能混寫，必須統一歸納至「非本期範圍（Out of Scope）」獨立章節，避免客戶產生錯誤期待或驗收爭議。
9. 當規劃文件需要呈現架構圖、流程圖（Data Flow）或循序圖（Sequence Diagram）時，Agent 應優先輸出標準的 Mermaid 或程式碼，而非嘗試直接生成圖片檔，以利後續開發者調整圖表與統一渲染風格，並確保圖表內文字與內文一致。
10. 來源必須可靠、可追溯且支援對應主張。可使用已確認的內部需求、既有設計與程式碼；未確認草稿不能當成定案依據，未取得的外部文件不能虛構引用。正文應自足，不以要求讀者另看內部草稿、未公開文件或其他章節代替必要說明。涉及通用法規或公開技術標準時，提供官方來源名稱及可查證連結。
11. 先概述本段需要的內容、機制或結果，再以「詳見某某章節」補充細節位置。不得只寫「見第 X 章」或只提供文件連結，讓閱讀者自行拼湊必要背景；交叉引用是補充，不是替代說明。
12. 文件上下用詞要保持一致。
13. 規劃文件用的圖片產出時，務必參照相關類型圖片的撰寫規範，避免資料庫名稱沒有統一、添加不必要的符號、容易有歧義的動作名稱。
14. 套用的技術要說明選用理由。
15. 產出 docx 或 PDF 文件時，「圖 X」這類編號都放在圖片下方；表格編號放在表格上方。
16. 避免放置非常見用語，以免造成客戶或其他開發者困惑。
17. 替換中國用語，開發者面對的場景多為台灣的單位。
18. 正式文件不可出現表情符號或 Emoji。
19. 正式文件產出時，必須包含「文件基本資訊」區塊，包含文件名稱、版本號（如 v1.0）、建立／更新日期，以及各章節的變更摘要，以符合正式文件的管控規範。
20. 規劃文件與 Data Flow 不可只寫順利執行的流程（Happy Path）。Agent 必須主動規劃並補齊邊界條件（Edge Cases）與錯誤處理機制（如：API 呼叫逾時、資料格式錯誤、斷線重連機制），並於文件中說明對應的系統行為。
21. 為確保轉出 docx 或 PDF 時的目錄結構正確，Agent 在撰寫 Markdown 時，標題層級最多下探至第四級（`####`）。若需更細節的分類，強制改用項目符號（Bullet points）或粗體標示，避免文件目錄過度碎裂。
22. 涉及系統架構與資料流規劃時，獨立說明身分驗證機制、適用的權限控管模型與資料傳輸加密標準。採用角色權限控管（RBAC）時描述角色及權限；其他模型依專案需求說明，不強制所有系統使用 RBAC。不適用或尚未決定的項目必須說明理由或列待確認，不虛構已採用機制。
23. 若規劃文件字數過長，Agent 應分章節產出。產出新章節時，必須嚴格檢視是否與前置章節的「名詞定義」、「系統架構」與「Data Flow」保持一致，避免前後邏輯斷裂或架構圖與內文對不起來。
24. 系統介接或應用程式介面（API）依實際協定使用一致的契約結構，說明呼叫或發布方、接收方、欄位與中文業務意義、請求或訊息格式、回應或處理結果，以及錯誤代碼與失敗行為。超文字傳輸協定（HTTP）介面包含方法、端點結構、請求與回應格式、狀態碼及錯誤代碼；事件、訊息與檔案介接描述其通道或位置、資料格式、處理結果及重送等適用語義，不硬套 HTTP 欄位。精確欄位名稱可出現，但不得使用未定義的自創代號或以代號代替說明。
25. 除功能性流程與資安（如第 22 點）外，若資訊充足，Agent 應主動在規劃文件中建立「非功能性需求」章節，包含預期效能（Response Time）、併發處理量（Concurrency）、資料保留策略（Data Retention）與系統可用性（Availability）的設計原則。

# 系統架構文件

產出讓業務、開發、維運與審查者能理解系統邊界、核對實作並檢驗設計的文件。文件預設使用台灣繁體中文，只有使用者明確要求時才改用其他語言；遵從使用者指定的契約章節與交付格式。此 skill 的規則是內部工作慣例，不等同任何認證標準。

## 共用文件規範

本技能用於系統規劃文件時，必須先讀取同層的 [系統文件撰寫與審核規範](../system-documentation-standard/SKILL.md)，並依其指示讀取 28 條核心規範。該規範優先於本技能與範本的交付預設；已讀取時不重複載入。僅處理獨立圖檔時採用相關命名、圖表及審查規則，不強制新增整份規劃文件。


## 選擇工作模式

- **新建完整架構書**：讀取 [撰寫 SOP](references/workflow.md) 與 [撰寫規範](references/writing-standard.md)，以 [架構書骨架](assets/architecture-template.md) 裁切章節。
- **單一功能 TDD**：讀取 SOP，使用 [TDD 骨架](assets/tdd-template.md)，交代變更前後、方案取捨、介面、失敗處理與 rollout，不強制擴成整本架構書。
- **從程式碼補文件／更新文件**：先鎖定版本與範圍；依 SOP 核對既有敘述。分開寫 As-is 與 To-be，保留未受影響內容與既有命名。
- **審查既有文件**：讀取 [審查規準](references/review.md)，提供證據、影響、修正與驗證方式；只有被要求修改時才改寫文件。
- 畫圖時讀取 [圖表邏輯](references/diagrams.md)；需要參考範例或解釋方法來源時讀取 [研究來源](references/sources.md)；需要示範如何串起證據、圖與驗收時讀取 [原創示例](references/worked-example.md)。不必每次重做網路研究。

## 工作底線

1. 先確認文件用途、讀者、系統邊界、版本與來源。優先讀取已提供資料；只詢問會改變主要架構或交付範圍的缺口，其餘列入待確認事項並繼續。
2. 對關鍵敘述區分 **已驗證、來源宣稱、假設、提案、待確認**。檔案存在不代表功能已部署；設計目標不代表量測成果；矛盾來源需並列版本與待裁決點。
3. 維持可追溯鏈：需求／品質目標 → 元件或介面 → 場景／圖 → 決策／風險 → 驗收方式。沿用專案 ID；無既有編號時只為需追蹤的項目建立 ID。
4. 先整理元件與關係，再繪圖；圖、正文、介面表使用同一名稱。未知拓樸、效能數字、模型準確度與已核准決策不可自行補成事實。
5. 深度以風險與讀者需要裁切。沒有適用性的內容寫明理由或省略；不得用大量空白章節冒充完整交付。草稿可保留明確缺口，正式完成判定依審查規準。
6. 交付前做跨章一致性與品質檢查，修正可直接修正的問題，保留仍需專案證據的事項。AI 自查不冒充人員簽核、測試執行或正式驗收。

# 架構文件審查規準

審查同時涵蓋設計完整性與合理性、與其他文件的架構矛盾及來源可靠性。正式正文不得混入內部討論、未定案推測或交付自查清單；業務驗收與追溯仍須依交付需求呈現。來源可靠性依確認狀態與主張檢查，不因內部來源而一律排除。委派其他 Agent 時要求第三方專家意見，提供位置、證據、影響與待討論問題，不以文字校對代替架構審核。

## 問題分級

- **阻擋交付**：會讓讀者依錯誤事實做重大決定，或核心範圍完全不可判讀。例如虛構已驗證成果、重大圖文矛盾、核心介面／資料責任不明。阻擋的是正式交付判定，不是停止整理可用草稿。
- **重大**：關鍵品質或操作路徑無法驗收，例如重試寫入但未交代重複效果、必須遷移卻沒有失敗回復策略。
- **一般**：局部缺漏造成理解或維護困難，尚不影響主要方案判斷。
- **建議**：可讀性或表達改善，非必要整改。

根據具體系統風險調整級別；不要看到某個詞缺席就自動升級。只檢查使用者指定範圍，未檢查部分標為未審查。

## 結論與門檻

- **可送人員審查**：核心內容有足夠依據、無未解的阻擋／重大問題；提案與未知已清楚揭露。這不等同人員核准。
- **需修訂**：存在足以影響設計、維運或驗收判斷的缺漏／矛盾。
- **資訊不足，僅可作草稿**：現有證據不足以確認核心現況或需求，仍應交付已完成內容與具體補件清單。

## 啟動順序（`src-tauri/src/main.rs`）

1. 寫入 HKCU 檔案關聯（`open_with::register_windows_association`，每次啟動都寫，exe 搬家後會自己更新）。
2. 解析 argv 裡的音訊路徑。如果已經有一個實例在跑，就把路徑透過 `127.0.0.1:47321` 轉交給它，然後自己結束。
3. 建立 `data/`、開啟 `data/app.db`，執行 `init_db`（缺欄才 `ALTER`，搜尋索引不符就重建）。
4. 啟動音訊執行緒 `start_player_thread`。
5. 建立 Tauri app，掛上 `DbState`、`PlayerState`、`OpenedFile`，在 `setup` 啟動單一實例監聽、系統匣與 SMTC。
6. 關閉視窗時，前端 `onCloseRequested` 先寫入工作階段，再呼叫 `destroy()`。Rust 端有 3 秒的看門狗，視窗還在就強制 `exit(0)`。

- 解碼走 symphonia（`audio_decode.rs`），不用 rodio Decoder 開檔；rodio Decoder 只在 `catch_unwind` 裡當後備，而且 mp4 家族的格式不走這條。
- 參數變更透過 `EqShared` 的版本號即時套用，不重開音源。只有 seek 與換裝置會重建 Sink 裡的音源。

## Symphonia 解碼限制（SE7）

- 配置前封包上限預檢 `precheck_packet_budget(path)`：在 `SymStream::open()` 之前執行，讀取檔案標頭遍歷所有音軌與片段的宣告封包大小（MP4 解析 stsz box；其他格式無法可靠遍歷時回傳 Ok，fail-open，依賴 `refill()` 第二層防護）；若任何封包宣告大小超過 256 KB，不呼叫 `open()`，回傳錯誤。
- `refill()` 第二層防護順序：取得封包 → 檢查 `packet.buf().len() > 256 KB`（超過即 `finished = true` 回傳 `false`）→ 音軌篩選 → `decoder.decode()`；大小檢查在音軌篩選之前，覆蓋所有音軌與後續片段。
- 四個 `SymStream::open` 入口（`player.rs:405`、`playback_pipeline.rs:1586`、`next_track.rs:92,298`）均先呼叫 `precheck_packet_budget(path)`，超標則拒絕不呼叫 `open()`。
- 解碼錯誤 `decode_errors` 欄位跨封包累計（`refill()` 迴圈內），超過 10 次即 `finished = true` 回傳 `false`；錯誤與成功封包交錯時仍繼續累計，不歸零。

## 程式需要的權限

| 項目 | 權限層級 | 說明 |
|---|---|---|
| 讀寫 `data/` | 一般使用者 | 位置是執行檔旁邊。放在唯讀的位置（例如 Program Files）會失敗，這是可攜式設計本來的限制 |
| 讀音樂資料夾 | 一般使用者 | 只讀，不刪改音樂檔；標籤編輯除外 |
| 寫標籤 | 一般使用者 | 只在使用者按下儲存時才寫，失敗的檔案逐一列出 |
| 檔案關聯 | 一般使用者（HKCU） | 每次啟動都寫，不寫 HKLM，不需要系統管理員 |
| 本機連接埠 47321 | 一般使用者 | 只綁 127.0.0.1，用來轉交右鍵開啟的路徑 |
| 子程序 | 一般使用者 | 都用 `Command::new` 加參數陣列，不經過 shell 字串 |
| 網路 | 一般使用者 | 只有使用者貼的電台網址，而且交給 ffmpeg 連線 |

目前**沒有任何功能需要系統管理員權限**。之後的規劃裡，可能需要提升權限或額外授權的項目（CD 抓軌、讓電腦從睡眠中被叫醒的工作排程器、獨佔輸出），在動手前都要先做小實驗，並寫進那個任務的 Design.md 與 Review.md（Security 節）。

## Tauri capability

- `src-tauri/capabilities/default.json`：`core:default` 加上視窗相關的權限（大小、最小化、最大化、隱藏、顯示、關閉、`allow-destroy`、置頂、全螢幕）。少了 `core:window:allow-destroy`，叉叉與系統匣的「結束」都會沒反應。
- 自訂 command：只要 `src-tauri/build.rs` 沒有用 `AppManifest::commands` 宣告，`invoke_handler` 註冊的 command 預設所有視窗都能呼叫（[Tauri 官方文件](https://v2.tauri.app/security/capabilities/)）。**一旦用 `AppManifest::commands` 宣告**，就要在 capability 裡列出每一個自訂 command，否則沒列到的會被拒絕（曲庫會變成空的）。單純加 plugin 不會擋掉自訂 command，但 plugin 本身的 API 要在 capability 裡加上對應的權限，並在 `main.rs` 用 `.plugin(...)` 註冊。
- `tauri.conf.json` 列了 dialog、fs、shell、notification，但 `Cargo.toml` 與 `package.json` 都沒有對應的 plugin，不能呼叫。選檔案和資料夾都走 PowerShell 對話框。
- CSP 是 `null`（沒有限制）。前端只載入打包好的資源，不載入遠端內容。

# 業務邏輯

改行為之前先讀對應章節。每一條都是使用者確認過、或修過 bug 才定下來的規則。

## 播放與播放模式

```mermaid
sequenceDiagram
  participant U as 使用者
  participant FE as Shell.tsx
  participant AE as AudioEngine
  U->>FE: 點兩下一首歌
  FE->>AE: player_load(path, songId)（會開始播）
  FE->>AE: player_play（保險）、player_set_volume(音量)
  FE->>AE: 依模式決定是否 player_preload(下一首)
  loop 每 250ms
    FE->>AE: player_status
    AE-->>FE: position、duration、ended、error…
  end
  AE-->>FE: ended = true（Sink 播空了）
  alt 順序模式
    FE-->>U: 停住，不接下一首
  else 單曲循環
    FE->>AE: 重新播同一首
  else 全部循環／隨機
    FE->>AE: player_load(下一首)
  end
```

- 四種模式：**順序**（這首播完就停）、**全部循環**、**隨機**、**單曲循環**。模式按鈕旁要顯示文字，而且順序與全部循環的圖示和顏色要不同。
- 手動按下一首永遠會換歌；單曲循環只在自然播完時重播同一首。
- 引擎不能自己接預載的下一首（這會繞過模式）。之後做無縫播放時，改成「引擎只接前端依模式預載的那一首」。
- `player_load` 會開始播；要停在某個位置但不出聲，用 `player_prepare`。先載入再暫停會漏出一點聲音。
- `player_load` 之後要直接呼叫 `playerSetVolume(音量)`，不能用 `muted ? 0 : 音量`，否則剛開始播的聲音會被歸零。
- 15 分鐘以上（或長度不明）的檔案用串流播放：不做峰值正規化，也不參與交叉淡化。交叉淡化只在兩首都是記憶體軌、而且模式是全部循環或隨機時混音。
- symphonia 0.5 不會修剪 AAC 開頭的 2112 個 priming 樣本（約 44ms），這是固定的，不是 seek 的 bug。

## 工作階段（重新開啟時接回進度）

- 存在 `app_config.session`。只在暫停、切歌、關閉時寫入，位置最多每 5 秒寫一次；不在 250ms 輪詢時寫。
- 啟動時停在上次的歌曲與位置，**不自動播放**。不存電台，也不自動重連電台。
- 曲庫裡已經不存在的 id（歌曲或佇列）直接丟掉，不報錯。
- 右鍵開啟與工作階段恢復同時發生時，以右鍵開啟的檔案為準：恢復流程的 token 要在任何 `await` 之前取樣（`openWithRestore.ts` 的 `sessionRestoreActions`）。

```mermaid
sequenceDiagram
  participant W as Windows
  participant N as 新程序

  participant FE as Shell.tsx
  W->>N: sonicledger.exe "C:\a.flac"
  N->>N: audio_arg() 從 argv 找出音訊路徑
  alt 已經有實例在跑
    N->>R: TCP 127.0.0.1:47321 傳送路徑

    R->>FE: open-file 事件
```

- 支援的副檔名以 `open_with.rs` 的清單為準，而且必須跟實際能解碼的格式一致（目前不一致，P0-2 會處理）。
- 開了視窗卻沒有出聲時，先看 `data/open-with.log`：沒有 argv 是檔案關聯的問題；有 `LOAD_ERR` 是解碼失敗；出現在 `LOAD_OK` 之後的 `CMD player_prepare`，代表工作階段恢復把剛開的歌換掉了。
- 拖放用 `classify_drop_cmd` 分類：一個檔案就直接播；資料夾就加入曲庫並掃描；拖進歌單頁籤的多個檔案就加入那個歌單，而且不換目前播放的歌。

## 曲庫與搜尋

- 缺檔標成 `missing=1`，不刪除列；掃描一個資料夾時，不能標記資料夾以外的歌。
- 音軌號與碟號存正整數或 NULL，不存 0。專輯檢視依碟號、音軌號、歌名排序；最近播放依播放時間排序。這兩個都不套用曲庫的排序鍵。
- 搜尋：每個詞都要符合（AND）。3 個字以上用 FTS5 trigram `MATCH`（任意位置的子字串、不分大小寫）；1–2 個字改用 `LIKE`。比對範圍是曲名、歌手、專輯、去空白的拼音、拼音首字母。搜尋結果要套用到清單上，不能只存在本機狀態裡。
- 歌曲清單必須虛擬捲動，10 萬首也不能一次畫成 DOM。
- 封面路徑是檔案系統路徑，要用 Tauri 的 file-src 轉換才能顯示。

## 掃描與標籤限制（SE7）

- lofty 讀取標籤前設定單欄 ≤ 4 KB、總標籤 ≤ 16 KB 上限；超過 16 KB 的總標籤拒絕整檔入庫（`Rejected`），單欄超 4 KB 由 `limited_tag()` 第二層裁切並記 `ScanError`，不中斷其他欄位。
- 不載入嵌入封面進記憶體：掃描前先執行 `has_embedded_cover_precheck(path)` 偵測 ID3v2 APIC、MP4 `covr`、FLAC 圖片區塊；偵測到嵌入封面直接拒絕入庫，不走 lofty 也不走 ffprobe 後備；`cover_path` 固定為 `None`。
- 取樣率驗證 8000–384000 Hz、聲道 1–8，超出視為無效（含 0 值）；不使用 `.filter(|v| *v > 0)` 過濾零值，先檢查 0 值再檢查範圍，非法值拒絕入庫並記 `ScanError`。
- ffprobe 後備讀取的標籤進入共同處理前，套用相同 4 KB／16 KB 預算。
- 掃描結果契約：`ScanResult::Song(NewSong, Vec<ScanError>)` 正常入庫、`ScanResult::Rejected(Vec<ScanError>)` 拒絕入庫但錯誤仍彙整、`ScanResult::Skipped` 檔案系統層級跳過；單一檔案錯誤不導致整個掃描失敗。

## 歌單

- 頁籤就是工作區：開歌單會釘一個頁籤，關頁籤不會刪歌單；「全部歌曲」永遠在。開著的頁籤存在 `playlist_tabs`。
- 側欄不放刪除按鈕；「全部歌曲」「最近播放」是檢視，不能刪。
- 排序寫入用 `playlist_items.id`，不是 `song_id`。
- 智慧歌單依規則重算，不存項目，不能拖曳或移除項目。規則只能用欄位白名單（`query_smart_playlist_songs`），不接受自由 SQL。
- m3u：只處理 UTF-8 的 `.m3u` 與 `.m3u8`。相對路徑以 m3u 所在的資料夾展開。對不到的行逐一列出，不能默默丟掉。

## 等化器與音效

- 18 段半八度：31、63、87、125、175、250、350、500、700、1K、1.4K、2K、2.8K、4K、5.6K、8K、11K、16K。各段與前級都是 ±15 dB，有總開關（關閉時各段與前級都不作用）。
- `design_gains` 解各段之間的互相干擾，讓每段中心頻率的實際響應等於推桿值；畫面上的曲線由 `eq_response_cmd` 用同一套算出來，不能在前端另算一套近似值。
- 十種音效：速度、節奏、音高、低音、高音增強、人聲消除、合唱、鑲邊、回音、殘響。全部關閉時輸出要跟輸入逐樣本相同。速度、節奏、音高不作用於電台。
- 改參數時不重開音源（不能每拖一下推桿就 `restart_from`）。
- 預設 `{ name, bands, preamp?, bind? }`。種子是本播放器自己調的曲線，只在沒有同名預設時補上；使用者可以覆寫、刪除。
- 自動套用的比對順序：綁定這首檔案 → 綁定這張專輯 → 綁定這個曲風 → 依曲風的內建建議 → 回退預設。每首歌只在換到它時套用一次，之後使用者手動調整不會被蓋回去。
- 情境建議會一次替換等化器、前級與音效；音效從預設值開始覆寫，不保留上一個情境的設定。

## 工具

- **批次標籤**：只改歌手、專輯、曲風、年份，不在同一批裡改曲名或音軌號。失敗的檔案逐一列出，不能用「整批成功」帶過。
- **轉檔**：本機有 ffmpeg 才執行，沒有就明說。mp3 顯示 128／192／320 kbps 選項，flac、wav、ogg 不顯示位元率。不顯示假的進度條。
- **電台**：只收使用者貼的 http/https 網址，不內建電台目錄，也不猜 ICY 資訊；ICY 的 stream title 持續顯示。電台用 ffmpeg 轉成 PCM 播放，沒有 ffmpeg 就明說。

## 視窗與系統整合

- 輸出裝置：列得出裝置才顯示下拉選單。過濾掉螢幕、HDMI 音訊（NVIDIA High Definition Audio、Intel Display Audio、AMD High Definition Audio Device、Microsoft LifeCam），系統預設裝置排第一個。切換時從目前位置接著播，電台會重新連線。
- 系統匣的「結束」會關閉視窗，讓關閉時的寫入照常執行。不搶全域的 `MediaPlayPause`（媒體鍵交給 SMTC）。設定裡不放媒體鍵開關。
- 迷你模式：同一個視窗縮成 480×200 並置頂；還原時回到 1200×800，最小尺寸 900×600。
- 睡眠計時：N 分鐘後暫停，或這首播完就停；只在視窗開著時有效。
- 版面從 900×600 最小尺寸起都要能用：頁尾分兩列；清單依自己量到的寬度藏欄（小於 760 藏日期、小於 600 藏軌號與次數、小於 460 藏專輯）。

41: ## 詳細設計
42: 
43: ### 4.1 長檔串流必須經 TrackResampler 重取樣（R1、R2）
44: 
45: `playback_pipeline.rs` `next_playing()`：
46: 
47: - 現行 `next_stream()`（line 397-400）從 `stream_source` 取得單一 `f32` 原生樣本，線程安全地鎖定 `stream_source` Mutex。
48: - `TrackResampler::process(sample: f32) -> Option<f32>`：餵入單一原生樣本，累積至 BLOCK_FRAMES（2048）後經 rubato 重取樣到 48kHz；回傳 `Some(48kHz 聲道樣本)` 或 `None`（累積中，非靜音，非結束）。**保留現有單樣本介面，不改為區塊介面。**
49: - `TrackResampler::pop_output() -> Option<f32>`：取出重取樣器內部已產出但尚未消耗的剩餘樣本；回傳 `None` 表示內部緩衝已耗盡。
50: - `PlaybackCore` 新增兩個佇列：
51:   - `track_out: Mutex<VecDeque<f32>>`：TrackResampler 輸出的 48kHz 聲道樣本暫存，**尚未經 DSP**。
52:   - `dsp_out: Mutex<VecDeque<f32>>`：DSP 最終輸出佇列（立體聲交錯），供 `next_playing()` 逐樣本消耗並回傳，**一個樣本即可回傳，不以兩個為門檻**。
53: - 修改 `next_playing()` 的串流軌分支（line 328-338）：
54:   1. 先從 `dsp_out` 佇列取樣本回傳；若 `dsp_out` 不空，回傳一個樣本並結束此次調用。
55:   2. 若 `dsp_out` 空，先從 `track_resampler` 的 `pop_output()` 取出剩餘重取樣輸出，追加至 `track_out`，直到 `pop_output()` 回傳 `None`（內部緩衝耗盡）。
56:   3. 若 `track_out` 夠兩個樣本，取兩個組成 `[L, R]`，送入 `apply_dsp_block(&[L, R], &mut tmp_out)`，將 `tmp_out` 全部追加至 `dsp_out`，回到步驟 1。
57:   4. 若 `track_out` 不足兩個樣本，呼叫 `next_stream()` 取得原生樣本。
58:   5. 鎖定 `track_resampler`，**必須**存在（長檔載入時 `player.rs:420` 已建立）；若為 `None` 回傳錯誤記錄並輸出靜音，不得繞過。
59:   6. 呼叫 `track_resampler.process(sample)`；回傳 `Some(s)` 時將 `s` 追加至 `track_out`；`None` 表示累積中，繼續拉取上游。
60: - 上游結束（`next_stream()` 回傳 `None`）且 `track_out`、`dsp_out` 皆耗盡後，進入軌結束流程（見 4.3）。
61: - 移除 line 337-338 的繞過路徑（`resampler` 為 `None` 時直接 `apply_dsp(sample)`）。
62: 
63: ### 4.2 apply_dsp_block 改為立體聲幀輸入、零到多幀輸出並併入 RateStage（R3）
64: 
65: `playback_pipeline.rs`：
66: 
67: - `PlaybackCore` 新增欄位：
68:   - `rate_stage: Mutex<Option<RateStage>>`（`RateStage` 在 `crate::dsp`，`dsp.rs:540`）；
69:   - `track_out: Mutex<VecDeque<f32>>`（TrackResampler 輸出暫存，未經 DSP）；
70:   - `dsp_out: Mutex<VecDeque<f32>>`（DSP 最終輸出佇列，立體聲交錯）；
71:   - `dsp_params: Mutex<Option<FxParams>>`（參數快照，命令執行緒更新，音訊執行緒讀取）。
72: - `PlaybackCore::new()`（line 135-162）中初始化 `rate_stage: Mutex::new(None)`、`track_out: Mutex::new(VecDeque::new())`、`dsp_out: Mutex::new(VecDeque::new())`、`dsp_params: Mutex::new(None)`。
73: - `dsp.rs` 需修正：`RateStage::new(channels: usize, sample_rate: u32)` 與 `RateStage::run(&mut self, input: &[f32], p: &FxParams, flush: bool, out: &mut Vec<f32>)` 目前為私有（line 547、550），須改為 `pub(crate)`，以便 `playback_pipeline.rs` 跨模組呼叫；`run` 保留 `&FxParams` 參數；`new()` 的 `channels` 參數為 `usize`，呼叫處傳入 `INTERNAL_CHANNELS as usize`。
74: - `FxParams` 沒有 `allow_rate` 欄位（`allow_rate` 是來源建構參數，見 `dsp.rs:617、630`）。以來源類型（本地長檔建立並啟用 RateStage、電台串流略過 RateStage，與 `Agents/business-logic.md` 第 99 條一致）決定是否建立／略過 RateStage。
75: - FxChain 必須經 `dsp.rs:311-324` 的 `set(&params)` 更新設定及配置效果狀態，再於每個立體聲幀上呼叫 `frame()`。
76: - 軌載入/切換時（初次載入、手動換軌、seek、自然交接），建立 `RateStage::new(INTERNAL_CHANNELS as usize, INTERNAL_SAMPLE_RATE)`，依來源類型設定是否啟用速度/節奏/音高。
77: - `apply_dsp_block(&self, frame: &[f32; 2], out: &mut Vec<f32>)`：餵入一立體聲幀 `[L, R]`，輸出零到多個處理後樣本追加至 `out`：
78:   1. 取得 `FxParams` 快照（`EqShared` 版本號，即時生效，參數不在區塊中途突變）；
79:   2. EQ（每聲道獨立，現有 `eq_processor`）；
80:   3. 速度/節奏/音高（`RateStage.run(input, &fx_params, flush, out)`，依 `FxParams`；電台略過 RateStage）；
81:   4. `FxChain` 音效（bass/enhancer/voice_remover/chorus/flanger/echo/reverb，立體聲幀 `&mut [f32; 2]`）；
82:   5. 正規化（`norm_gain`）；
83:   6. 限幅 `clamp(-1.0, 1.0)`。
84: - `next_playing()` 從 `dsp_out` 佇列取樣本回傳；若 `dsp_out` 空且 `track_out` 空，繼續拉取上游 `next_stream()` → `TrackResampler::process()` → 組成立體聲幀 → `apply_dsp_block()` 直到 `dsp_out` 有樣本或上游結束；上游結束且兩佇列皆耗盡則進入軌結束流程（見 4.3）。
85: - `FxChain::frame(f: &mut [f32])` 已依聲道索引處理（`dsp.rs:332-386`），傳入長度為 2 的切片即可正確處理左右聲道。

87: ### 4.3 軌切換與身分/邊界發布
88: 
89: - `TrackResampler.flush_tail()` / `commit_boundary()` / `set_track()` 在軌切換時已由 `sync_identity()`（line 412-481）序列化：先 flush_tail 舊軌尾端 → commit_boundary 寫入邊界 → set_track 切換到新軌。
90: - 軌切換時 `RateStage` 與舊軌尾端的處理順序（參考 `DspSource::fill()` EOF 路徑 `dsp.rs:659-669`）：`sync_identity()` 先以 `TrackResampler.flush_tail()` 將上游舊軌尾端移至 `pending_output`（`playback_pipeline.rs:432-444`）；舊軌尾端樣本先經 EQ（每聲道獨立，與 `apply_dsp_block()` 第 1 步一致），再以 `flush=false` 逐幀送入舊 `RateStage.run()`，讓 WSOLA / Resampler 正常累積與變速/變調處理；全部餵完後，以空輸入呼叫一次 `RateStage.run(&[], &fx_params, flush=true, ...)`，以 `wsola.drain_raw()` / `rs.drain_raw()` 排空內部殘餘（`dsp.rs:550-568`，與來源結束時 EOF 排空同路徑 `dsp.rs:659-669`）。步驟的 `run` 產出（已過 EQ 與 RateStage）僅經後續音效 → 正規化 → 限幅排出，不再重複進入 RateStage 或 EQ，與正常資料的 `apply_dsp_block()`（EQ → RateStage → 音效 → 正規化 → 限幅）於 RateStage 後方階段對齊，確保無縫；最後才捨棄舊 `RateStage` 並建立新實例。故重建不會截斷舊軌尾端。
91: - `dsp_out` 生命週期（R2-4）：
92:   - 自然交接：舊軌輸出完全排完 `dsp_out` 後，才進入下一軌。
93:   - 手動換軌／seek 安裝新來源前：清空 `track_out` 與 `dsp_out`、重設 RateStage 終結狀態，避免舊位置殘留聲音跳出。
94: - `boundary_in_48k` 由 `TrackResampler.boundary_in_48k()` 發布；`boundary_out_48k` 以舊軌最後一個 DSP 輸出幀的位置提交（DSP 檢查點映射列為待實作，`playback_pipeline.rs:53-55` 目前僅為註解，實際 453-455 行直接使用 `current_boundary_out_start()`，初值為 0）。
95: 
96: ### 4.4 錯誤處理
97: 
98: - `TrackResampler` 為 `None` 時（長檔載入失敗）：記錄 `log_line`，`next_playing()` 輸出靜音幀，不 panic。
99: - `RateStage` / `FxChain` 處理錯誤：現有 `log_line` 記錄，輸出靜音幀，不中斷播放。
100: - `next_stream()` 回傳 `None`（串流來源結束）：上游只 flush 一次（`flush_tail`）→ 全部尾端樣本先經 EQ → 舊 `RateStage`（`flush=false` 全部餵入，最後單次 `flush=true` 排空殘餘）→ 音效 → 正規化 → 限幅 → 進 `dsp_out`；`dsp_out` 耗盡後進入 `WaitingForNext`。`RateStage` 只終結一次，不可重複呼叫 `flush_tail()` 或再次 flush 上游（rubato `process_partial(None)` 是補零區塊，非「是否已排空」的查詢，重複呼叫會反覆產生輸出，無法穩定進入等待分支）。

319:                     self.add_played_out_frames(1);
320:                 }
321:                 s
322:             }
323:             PlaybackState::WaitingForNext | PlaybackState::Paused | PlaybackState::Finished => Some(0.0),
324:         }
325:     }

327:     /// Playing 狀態下的取樣：串流軌直接來源 → 原生樣本 → 重取樣 → EQ/正規化。
328:     fn next_playing(&self) -> Option<f32> {
329:         // 串流軌直接來源（適用長檔與 ffmpeg 串流），需經 TrackResampler 重取樣到 48kHz
330:         if let Some(sample) = self.next_stream() {
331:             let mut resampler = self.track_resampler.lock().unwrap();
332:             if let Some(r) = resampler.as_mut() {
333:                 match r.process(sample) {
334:                     Some(s) => return Some(self.apply_dsp(s)),
335:                     None => return Some(0.0), // 重取樣器仍在累積區塊，回靜音
336:                 }
337:             }
338:             return Some(self.apply_dsp(sample));
339:         }
340:         loop {
341:             // 優先排出重取樣器已緩衝的 48kHz 輸出（含軌切換時的尾端資料）
342:             {
343:                 let mut resampler = self.track_resampler.lock().unwrap();
344:                 if let Some(r) = resampler.as_mut() {
345:                     if let Some(s) = r.pop_output() {
346:                         return Some(self.apply_dsp(s));
347:                     }
348:                 }
349:             }
350: 
351:             // 從 TrackChain 拿一個原生樣本；軌結束時 TrackChain 自行從待播槽 take 下一軌，
352:             // 若槽也為空則回傳 None，代表這條鏈結束。
353:             let sample = {
354:                 let mut chain = self.track_chain.lock().unwrap();
355:                 match chain.as_mut().and_then(|c| c.next()) {
356:                     Some(s) => s,
357:                     None => {
358:                         // 鏈結束：先排出舊軌的重取樣器尾端資料，再進入 WaitingForNext
359:                         {
360:                             let mut resampler = self.track_resampler.lock().unwrap();
361:                             resampler.as_mut().map(|r| r.flush_tail());
362:                         }
363:                         {
364:                             let mut resampler = self.track_resampler.lock().unwrap();
365:                             if let Some(r) = resampler.as_mut() {
366:                                 if let Some(s) = r.pop_output() {
367:                                     return Some(self.apply_dsp(s));
368:                                 }
369:                             }
370:                         }
371:                         *self.playback_state.lock().unwrap() = PlaybackState::WaitingForNext;
372:                         return Some(0.0);
373:                     }
374:                 }
375:             };
376: 
377:             // 同步身分（seq / token / 正規化增益）：只有軌切換時會變動。
378:             // 軌切換時會 flush_tail 舊軌、commit_boundary、再切換重取樣器到新軌。
379:             self.sync_identity();
380: 
381:             // 重取樣到 48kHz 雙聲道；若回傳 None 代表重取樣器仍在累積區塊，繼續餵入
382:             let out = {
383:                 let mut resampler = self.track_resampler.lock().unwrap();
384:                 match resampler.as_mut() {
385:                     Some(r) => r.process(sample),
386:                     None => None,
387:                 }
388:             };
389:             match out {
390:                 Some(s) => return Some(self.apply_dsp(s)),
391:                 None => continue,
392:             }
393:         }
394:     }

398:         let mut src = self.stream_source.lock().unwrap();

407:     /// 檢查 TrackChain 目前軌的身分，若與 now_seq/now_token 不同則發布新身分。
408:     /// 軌交接發生在 TrackChain 讀完目前軌並從待播槽 take 新軌時。
409:     ///
410:     /// 順序：flush_tail 舊軌尾端 → commit_boundary 寫入邊界 → set_track 切換重取樣器。
411:     /// 兩把鎖不同時持有，避免鎖序倒置。
412:     fn sync_identity(&self) {
413:         let (seq, token, song_id, norm_gain, duration_ms, native_sample_rate, native_channels, path, decoder) = {
414:             let chain = self.track_chain.lock().unwrap();
415:             let Some(cur) = chain.as_ref().and_then(|c| c.current()) else { return };
416:             if cur.seq == self.now_seq() && cur.token == self.now_token() {
417:                 return;
418:             }
419:             (
420:                 cur.seq,
421:                 cur.token,
422:                 cur.song_id,
423:                 cur.norm_gain,
424:                 cur.duration_ms,
425:                 cur.sample_rate,
426:                 cur.channels,
427:                 cur.path.clone(),
428:                 cur.decoder.clone(),
429:             )
430:         };
431: 
432:         // 先把舊軌殘餘輸入排成尾端，再提交邊界（output_frames 含尾端會累進到 accum）
433:         {
434:             let mut resampler = self.track_resampler.lock().unwrap();
435:             resampler.as_mut().map(|r| r.flush_tail());
436:             resampler.as_mut().map(|r| r.commit_boundary());
437:         }
438:         // 軌切換時的尾端樣本已由 flush_tail 移至 pending_output，不在此丟棄；
439:         // 下次 next_playing() 會優先從 pending_output 彈出，確保無縫輸出。
440:         {
441:             let chain = self.track_chain.lock().unwrap();
442:             if let Some(item) = chain.as_ref().and_then(|c| c.current()).cloned() {
443:                 let mut resampler = self.track_resampler.lock().unwrap();
444:                 resampler.as_mut().map(|r| r.set_track(Some(item)));
445:             }
446:         }
447:         let boundary_in_48k = self.track_resampler.lock().unwrap().as_ref().unwrap().boundary_in_48k();
448: 
449:         // 身分（seq/token）在軌切換時立即發布；進度與邊界則在舊軌尾端（pending_output）完全輸出後再重置，
450:         // 避免身分提前切換卻進度歸零，導致交界處的位置錯誤。
451:         self.set_now_identity(seq, token);
452:         self.current_norm_gain_bits.store(norm_gain.to_bits() as u64, Ordering::Release);
453:         self.push_boundary(BoundaryRecord {
454:             boundary_in_48k,
455:             boundary_out_48k: self.current_boundary_out_start(),
456:             seq,
457:             token,
458:             song_id,
459:             norm_gain,
460:             duration_ms,
461:             native_sample_rate,
462:             native_channels,
463:         });
464: 
465:         // 只有在舊軌尾端完全輸出後，才重置進度與邊界起點
466:         {
467:             let resampler = self.track_resampler.lock().unwrap();
468:             if let Some(r) = resampler.as_ref() {
469:                 if !r.pending_output_is_empty() {
470:                     return;
471:                 }
472:             }
473:         }
474:         self.reset_played_out_frames();
475:         self.set_current_boundary_in_start(boundary_in_48k);
476:         // 交接回呼：通知引擎更新 current_path/current_decoder（交接後 seek 需用正確路徑）
477:         if let Some(cb) = self.on_track_change.lock().unwrap().as_ref() {
478:             cb(seq, token, &path, &decoder);
479:         }
480:         log_line(&format!("TRACK_HANDOFF seq={} token={} song_id={}", seq, token, song_id));
481:     }

483:     /// 套用 EQ、音效鏈與峰值正規化（48kHz 單一樣本）。
484:     fn apply_dsp(&self, sample: f32) -> f32 {
485:         // 先套用 EQ
486:         let mut eq = self.eq_processor.lock().unwrap();
487:         let mut s = match eq.as_mut() {
488:             Some(p) => p.process(sample),
489:             None => sample,
490:         };
491:         drop(eq);
492: 
493:         // 再套用音效鏈（殘響、節奏、音高、回音等）
494:         let mut fx = self.fx_chain.lock().unwrap();
495:         if let Some(mut p) = fx.as_mut() {
496:             // FxChain::frame 期望一幀（所有聲道），這裡以單聲道幀處理
497:             let mut frame = [s];
498:             p.frame(&mut frame);
499:             s = frame[0];
500:         }
501:         drop(fx);
502: 
503:         if self.normalize() {
504:             let norm = f32::from_bits(self.current_norm_gain_bits.load(Ordering::Acquire) as u32);
505:             s = s * norm.clamp(0.0, 8.0);
506:         }
507:         s.clamp(-1.0, 1.0)
508:     }
509: }

820:     /// 切換到新軌（由 TrackChain 呼叫）。呼叫者應在切換前先自行 `flush_tail()` 排出舊軌尾端。
821:     pub fn set_track(&mut self, track: Option<TrackChainItem>) {
822:         self.current_track = track.map(|t| TrackResamplerTrack {
823:             sample_rate: t.sample_rate,
824:             channels: t.channels,
825:             duration_ms: t.duration_ms,
826:             song_id: t.song_id,
827:             norm_gain: t.norm_gain,
828:             token: t.token,
829:             seq: t.seq,
830:         });
831: 
832:         self.resampler = None;
833:         self.input_buffer.clear();
834:         self.frames_in_buffer = 0;
835:         self.output_buffer.clear();
836:         self.output_pos = 0;
837:         self.input_frames = 0;
838:         self.output_frames = 0;
839:         self.tail_flushed = false;
840: 
841:         if let Some(ref ct) = self.current_track {
842:             // 建立新的重取樣器
843:             let params = SincInterpolationParameters {
844:                 sinc_len: 256,
845:                 f_cutoff: 0.95,
846:                 interpolation: SincInterpolationType::Linear,
847:                 oversampling_factor: 256,
848:                 window: WindowFunction::BlackmanHarris2,
849:             };
850: 
851:             let resampler = SincFixedIn::<f32>::new(
852:                 INTERNAL_SAMPLE_RATE as f64 / ct.sample_rate as f64,
853:                 2.0,
854:                 params,
855:                 BLOCK_FRAMES,
856:                 INTERNAL_CHANNELS as usize,
857:             ).expect("Failed to create resampler");
858: 
859:             self.resampler_delay_frames = resampler.output_delay();
860:             self.resampler = Some(resampler);
861:         }
862:     }

864:     /// 排出舊軌殘餘的輸入與重取樣器延遲，產出尾端資料到 output_buffer。
865:     /// 在換軌或鏈結束前呼叫，避免丟失最後一段不足 BLOCK_FRAMES 的資料。
866:     pub fn flush_tail(&mut self) {
867:         let internal_ch = INTERNAL_CHANNELS as usize;
868:         let Some(resampler) = self.resampler.as_mut() else { return };
869:         let Some(ct) = self.current_track.as_ref() else { return };
870:         let ch = ct.channels as usize;
871:         let remaining = self.frames_in_buffer;
872: 
873:         // 即使 input_buffer 為空，也要排空 rubato 內部的延遲緩衝（尾端補樣）
874:         let block_samples: Vec<f32> = if remaining > 0 {
875:             self.input_buffer.drain(..).collect()
876:         } else {
877:             Vec::new()
878:         };
879:         let block: Vec<Vec<f32>> = (0..internal_ch)
880:             .map(|c| {
881:                 (0..remaining)
882:                     .map(|i| {
883:                         let native_idx = i * ch + if c < ch { c } else { 0 };
884:                         block_samples[native_idx]
885:                     })
886:                     .collect()
887:             })
888:             .collect();
889:         // 傳入 None 當 input 表示 flush 處理（rubato 會把內部殘餘輸出）
890:         // 使用 process（而非 process_partial）以避免類型轉換問題，partial 區塊由 rubato 直接處理
891:         let input_ref: Option<&[Vec<f32>]> = if remaining > 0 { Some(&block) } else { None };
892:         match resampler.process_partial(input_ref, None) {
893:             Ok(out) => {
894:                 let n = out.first().map(|v| v.len()).unwrap_or(0);
895:                 for f in 0..n {
896:                     for c in 0..internal_ch {
897:                         self.output_buffer.push(out[c][f]);
898:                     }
899:                 }
900:                 self.output_frames += n as u64;
901:             }
902:             Err(e) => {
903:                 log_line(&format!("track resampler flush_tail error: {e}"));
904:             }
905:         }
906:         self.frames_in_buffer = 0;
907:         self.input_frames += remaining as u64;
908:         // 將 output_buffer 中已產出的尾端樣本移到 pending_output，確保不被 set_track 清除
909:         self.pending_output.extend(self.output_buffer.drain(..));
910:         self.tail_flushed = true;
911:     }
912: 
913:     /// 取出一個已緩衝的 48kHz 輸出樣本。
914:     pub fn pop_output(&mut self) -> Option<f32> {
915:         // 優先回傳軌切換時保留的尾端樣本
916:         if !self.pending_output.is_empty() {
917:             return Some(self.pending_output.remove(0));
918:         }
919:         if self.tail_flushed && self.output_pos >= self.output_buffer.len() {
920:             return None;
921:         }
922:         if self.output_pos >= self.output_buffer.len() {
923:             if !self.output_buffer.is_empty() {
924:                 self.output_buffer.clear();
925:                 self.output_pos = 0;
926:             }
927:             return None;
928:         }
929:         let s = self.output_buffer[self.output_pos];
930:         self.output_pos += 1;
931:         Some(s)
932:     }
933: 
934:     /// 處理輸入樣本，累積完整 BLOCK_FRAMES 區塊後才呼叫 rubato 重取樣，
935:     /// 並從 output_buffer 產出 48kHz 雙聲道樣本。
936:     pub fn process(&mut self, input: f32) -> Option<f32> {
937:         if self.current_track.is_none() {
938:             return None;
939:         }
940: 
941:         let ch = self.current_track.as_ref().unwrap().channels as usize;
942:         let internal_ch = INTERNAL_CHANNELS as usize;
943: 
944:         self.input_buffer.push(input);
945:         // 只有湊齊一個 native frame（ch 個樣本）才計入框計數
946:         if self.input_buffer.len() % ch != 0 {
947:             return self.pop_output();
948:         }
949:         self.frames_in_buffer += 1;
950: 
951:         // 累積到滿一個 rubato 區塊再處理；不足時回傳已緩衝的輸出（若有）
952:         if self.frames_in_buffer < BLOCK_FRAMES {
953:             return self.pop_output();
954:         }
955: 
956:         // 取出 BLOCK_FRAMES 個 native frame，轉成 rubato 非交錯格式（內建 internal_ch 聲道）
957:         let block_samples: Vec<f32> = self.input_buffer.drain(..).collect();
958:         let block: Vec<Vec<f32>> = (0..internal_ch)
959:             .map(|c| {
960:                 (0..BLOCK_FRAMES).map(|i| {
961:                     let native_idx = i * ch + if c < ch { c } else { 0 };
962:                     block_samples[native_idx]
963:                 }).collect()
964:             })
965:             .collect();
966:         if let Some(ref mut resampler) = self.resampler {
967:             match resampler.process(&block, None) {
968:                 Ok(out) => {
969:                     let n = out.first().map(|v| v.len()).unwrap_or(0);
970:                     for f in 0..n {
971:                         for c in 0..internal_ch {
972:                             self.output_buffer.push(out[c][f]);
973:                         }
974:                     }
975:                     self.output_frames += n as u64;
976:                 }
977:                 Err(e) => {
978:                     log_line(&format!("track resampler process error: {e}"));
979:                 }
980:             }
981:         }
982:         self.frames_in_buffer = 0;
983:         self.input_frames += BLOCK_FRAMES as u64;
984: 
985:         self.pop_output()
986:     }

163:     fn spawn_recycle_thread(rx: Receiver<RecycleItem>, cancel_flag: Arc<AtomicBool>, coordinator: Arc<crate::playback_pipeline::NextCoordinator>) -> thread::JoinHandle<()> {
164:         thread::spawn(move || {
165:             // SE9：回收期間凍結新準備工作（quota freeze），超過 30 秒仍未結束標記孤兒
166:             while !cancel_flag.load(Ordering::Relaxed) {

91: fn peaking(sample_rate: f64, freq: f64, gain_db: f64) -> Option<Coef> {
92:     if gain_db.abs() < 0.01 || sample_rate <= 0.0 || freq >= sample_rate * 0.48 {
93:         return None;
94:     }
95:     let a = 10f64.powf(gain_db / 40.0);
96:     let w0 = 2.0 * PI * freq / sample_rate;
97:     let alpha = w0.sin() / (2.0 * Q);
98:     let cosw = w0.cos();
99:     let a0 = 1.0 + alpha / a;
100:     Some(Coef {
101:         b0: (1.0 + alpha * a) / a0,
102:         b1: (-2.0 * cosw) / a0,
103:         b2: (1.0 - alpha * a) / a0,
104:         a1: (-2.0 * cosw) / a0,
105:         a2: (1.0 - alpha / a) / a0,
106:     })
107: }

109: fn coef_db(c: &Coef, sample_rate: f64, freq: f64) -> f64 {
110:     let w = 2.0 * PI * freq / sample_rate;
111:     let (c1, s1, c2, s2) = (w.cos(), w.sin(), (2.0 * w).cos(), (2.0 * w).sin());
112:     let nr = c.b0 + c.b1 * c1 + c.b2 * c2;
113:     let ni = -(c.b1 * s1 + c.b2 * s2);
114:     let dr = 1.0 + c.a1 * c1 + c.a2 * c2;
115:     let di = -(c.a1 * s1 + c.a2 * s2);
116:     10.0 * ((nr * nr + ni * ni) / (dr * dr + di * di)).log10()
117: }

128: fn solve(mut m: [[f64; BANDS]; BANDS], mut y: [f64; BANDS]) -> Option<[f64; BANDS]> {
129:     for c in 0..BANDS {
130:         let p = (c..BANDS).max_by(|a, b| m[*a][c].abs().total_cmp(&m[*b][c].abs()))?;
131:         if m[p][c].abs() < 1e-9 {
132:             return None;
133:         }
134:         m.swap(c, p);
135:         y.swap(c, p);
136:         for r in 0..BANDS {
137:             if r != c {
138:                 let k = m[r][c] / m[c][c];
139:                 for j in c..BANDS {
140:                     m[r][j] -= k * m[c][j];
141:                 }
142:                 y[r] -= k * y[c];
143:             }
144:         }
145:     }
146:     let mut out = [0.0; BANDS];
147:     for i in 0..BANDS {
148:         out[i] = y[i] / m[i][i];
149:     }
150:     Some(out)
151: }

154: pub fn design_gains(bands: &[f32; BANDS], sample_rate: f64) -> [f64; BANDS] {
155:     let target: [f64; BANDS] = std::array::from_fn(|i| bands[i] as f64);
156:     if target.iter().all(|g| g.abs() < 0.01) {
157:         return [0.0; BANDS];
158:     }

160:     let usable: [bool; BANDS] = std::array::from_fn(|i| (EQ_HZ[i] as f64) < sample_rate * 0.48);
161:     let mut g = target;
162:     for _ in 0..3 {
163:         let mut m = [[0.0; BANDS]; BANDS];
164:         for j in 0..BANDS {
165:             if !usable[j] {
166:                 m[j][j] = 1.0;
167:                 continue;
168:             }

170:             let c = peaking(sample_rate, EQ_HZ[j] as f64, probe);
171:             for i in 0..BANDS {
172:                 if usable[i] {
173:                     m[i][j] = c.as_ref().map(|c| coef_db(c, sample_rate, EQ_HZ[i] as f64)).unwrap_or(0.0) / probe;

176:         }
177:         let mut y = target;
178:         for i in 0..BANDS {
179:             if !usable[i] {

181:             }
